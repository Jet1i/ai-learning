# 第 11 周 Q&A

## FlashAttention 省了什么?(L2)
- 省:N×N 分数矩阵不落显存 → attention 的显存读写少(更快)+ 不用存 N×N(长上下文放得下)。
- 不省:计算量、KV cache、权重。
- L2 账里:prefill 只按 2×参数 算 FLOPs = 默认开了 Flash;decode 读权重 + KV,Flash 不影响。

## 自建 8B 的钱怎么算?(L2)
1. decode:batch 64 × 上下文 3750 × 128 KB = 30.7 GB KV + 16 GB 权重 = 46.7 GB;÷ 2 TB/s = 23.4 ms/步;64 ÷ 0.0234 = 2740 tok/s × 0.4 = 1096。
2. prefill:312 TFLOPs ÷ (2 × 8e9) = 19500 tok/s × 0.4 = 7800。
3. 每次请求 = 3600/7800 + 300/1096 = 0.735 s → 每卡 1.36 次/秒。
4. 平均 11.6 次/秒,高峰 ×1.82 = 21.1 → ⌈21.1/1.36⌉ = 16 卡 × 1.8 万 + 运维 3 万 = 31.8 万/月,利用率 53%。
公式:月成本 = ⌈高峰请求/秒 ÷ 每卡请求/秒⌉ × 卡时价 × 720 + 运维;每卡请求/秒 = 效率 ÷ (输入/prefill 速度 + 输出/decode 速度)。

## batch 64 怎么定的?上下文为什么 + 输出/2?
- batch 是假设。三个约束:① 显存:(80 − 16 − 4) GB ÷ 0.48 GB/请求 ≈ 125 个上限(vLLM PagedAttention 自动按块分配);② 吞吐边际递减:batch 1/16/64/125 → 121/1350/2740/3290 tok/s(权重分摊,KV 不能分摊);③ 每用户速度:121/84/43/26 tok/s。取"显存上限"和"用户可接受速度"之间,真实方案用 vLLM 压测调 max_num_seqs。
- KV 在生成中从 3600 涨到 3900,decode 每步读当时的 KV,平均 = 中点 3750;batch 里的请求阶段各不同,平均也是中点。

## 128 KB 是什么?
LLaMA-3 8B 每个 token 的 KV cache:2(K、V)× 32 层 × 8 个 KV 头(GQA)× 128 维 × 2 字节 = 131072 B = 128 KB。× 3750 token ≈ 0.48 GB/请求。MHA(32 个 KV 头)= 512 KB,60 GB 只能塞约 31 个请求 vs 125 个 → GQA/MLA 省 KV = 能服务的人数 = 成本。

## 私有化为什么按峰值买?对利用率和成本的影响?
8B、100 万次/天、每卡 1.36 次/秒:每小时需要的卡 1~16 张(凌晨 1,10 点/15 点 16)。
- 云上完美弹性:一天 214 卡时,利用率约 95%。
- 私有化:买 16 张 × 24 h = 384 卡时,利用率 53%,多付 1.8 倍卡时。
原因:采购上架要几周到几个月(不能临时加)、买了不能退、还要加备机和增长余量 → 刚上线利用率更低。成本固定,单次成本 = 固定成本 ÷ 实际请求数。
现实:云弹性也不完美(GPU 可能租不到、启动几分钟、按需价更贵)→ 基础量包年 + 高峰按需。私有化补救:削峰(排队)+ 填谷(夜间跑批)。

## inject.py 实测 + guard 怎么做到的
- Jet 在 Mac 上实测 DeepSeek:v1(明显的"系统通知")、v2(伪装成折扣流程)、v3(v2 + 用户说"按文件流程处理")三种模式全是 0/3 → 新模型能识破这几种写法,但 9 次 ≠ 永远安全。
- guard = run_tool() 里的普通 if:收件人域名白名单 + 读过外部内容后要用户确认。模型只输出 tool_call JSON(第 4 周),执行权在代码 → 模型被骗也执行不了。
- MODEL=fake(一定会被骗的假模型):naive 3/3 发出,prompt 3/3,guard 0/3。假模型被拦了还对用户说"已提交" → 工具失败要如实反馈 / 审计日志。

## L4 练习参考答案(Jet 要求直接给)
1. 0/3:模型受过训练(工具结果 = 数据、外发客户名单 = 高风险);不能说明换写法/换模型/更多次数/多步隐蔽攻击也安全(9 次测不出 1% 的被骗率)。
2. prompt 防护:同一串 token、没有权限隔离,攻击者可离线迭代 → 只能降概率。
3. guard = 代码里的 if;绕过白名单:内部邮箱自动转发、Markdown 图片地址带数据(前端渲染即外发)、网页工具 URL、对外共享文档 → 管所有出口(URL 白名单、不自动加载外部图片)、DLP 扫描、确认时展示完整内容;"已提交"谎话 → UI 以代码执行记录为准 + 审计日志。
4. 三要素:报价对比不需要客户名单 → 最小权限只读报价目录;或不给 send_email 只写草稿;或隔离模型只输出结构化字段。代价:自动化降低。
5. 售前:不能保证 100%,目标是"被骗也造不成损失":最小权限、代码硬规则、输入输出过滤/DLP、审计+监控、上线前红队(攻击用例集 + 拦截率)。

## 高风险动作的用户确认也是 tool 实现的吗?
不是。写在 agent 循环代码里,夹在"模型提出 tool_call"和"执行"之间:查风险表 → 高风险就暂停 → UI 展示完整参数 → 用户点按钮直接送到代码(模型写不进这个通道)→ 同意执行 / 拒绝把"用户拒绝"作为工具结果还给模型。做成 tool 的话模型被骗可以跳过,或相信"用户已同意"的伪造文本。真实网页系统:待确认动作存数据库、推卡片、点完再续跑(LangGraph interrupt);例子:Claude Code 的权限确认。

## 问数 agent 的"模糊提问先确认"也写在 loop 里吗?
机制一样(循环暂停等用户),但谁决定不同:澄清 = 质量问题,通常模型判断(prompt / ask_user 工具),漏了只是答偏;审批 = 安全问题,必须代码。标准:漏掉的后果能不能接受。问数里代码也能强制澄清:指标多口径(语义层匹配 2 个定义)、实体重名、SQL 无时间条件扫全表。问数的安全项全在代码/数据库:只读账号、行级权限、敏感字段脱敏。

## "待确认动作存进数据库"是什么意思?
网页服务不能 input() 干等(用户可能 2 小时后才点、几千用户、HTTP 超时、重启丢内存)→ 拆成两次请求:① 跑到高风险 tool_call 停下,存一行(action_id、user_id、tool/args、完整 messages、status=pending、过期时间),返回确认卡,请求结束;② 用户点同意 → 读出这行,校验用户/状态/过期 → 执行、status=done → 把结果接进 messages 继续循环。顺带:防重复点击、防冒充、审计。比喻:服务员把点到一半的单子记在本子上。LangGraph interrupt + checkpointer。

## 客户 VPC 是什么?是单独的 GPU 吗?
VPC = 客户自己云账号下隔离的私有网络(网段、机器、出入口由客户控制),说的是网络和账号归属,不是 GPU。比喻:写字楼大堂(①共享 API)/ 物业留的会议室(③专属实例,钥匙在物业)/ 租下一整层(④VPC,钥匙在你)/ 自己的楼(⑤)。④里租的 GPU 云服务器整张独占,但③也独占;区别在账号/网络归谁、谁运维模型、数据经过谁的系统。④硬件物理上仍在厂商机房 → 要信任厂商虚拟化;金融云/政务云多可接受,涉密只能⑤。

## L4b 练习要点(批改 ~2.6/5)
1. 后过滤:本租户可能被挤出 top-k(召回差)+ 别家文档已被读取打分 + 依赖"记得过滤" → 先过滤 / 独立索引。
2. "正则抓" = 固定模式匹配;抓不到名字地址、换说法、组合可识别信息、商业机密(非个人信息)→ 业务数据整体不能出域时必须私有化。
3. 原文加密单独存,钥匙给审计角色,查看本身记日志、双人审批。

## GPU 卡怎么选?按显存吗?
显存是门槛不是标准;标准 = 每次请求成本。四关:① 放得下(权重 + KV + 10%;32B int8 batch 64 = 93 GB)② 跑得快(decode 看带宽、prefill 看算力;RAG 输入长 → 算力重要)③ 多卡互联(NVLink vs PCIe)④ 买得到/合规(出口管制、信创国产卡 + vLLM 适配)。
32B 银行场景(卡价为示例):A100 80G batch 40 0.40 次/秒 1.7 分/次 11 卡 22.8 万;H20 96G batch 56 0.24 次/秒 3.5 分 18 卡 41.9 万(算力 148T,prefill 近 4 秒);H200 141G 1.23 次/秒 1.1 分 4 卡 17.4 万。最贵的卡最省;H20 适合输出长输入短的业务。流程:能买到的卡 → 筛显存 → 填 tco_gpu.py → 最低月成本且延迟达标 → vLLM 实测。

## 显存不是 SSD 吗?为什么 GPU 卡也有显存?
SSD = 存储(断电保留、TB 级、几 GB/s,模型文件放这里);显存 = GPU 卡上自带的内存(HBM,断电清空、80~141 GB、2~4.8 TB/s)。四层:SSD(仓库)→ 内存 RAM(柜子)→ 显存(桌面)→ SRAM(手边)。启动时模型从 SSD 一次性搬进显存,之后每个 token 只读显存:8B 16 GB ÷ 2 TB/s = 8 ms vs ÷ 7 GB/s ≈ 2.3 s。Mac M 系列 = 统一内存,CPU/GPU 共用。

## 4090 是多少?
RTX 4090:24 GB、约 1.0 TB/s、fp16 约 165 T、PCIe 无 NVLink。银行场景(3 元/卡时示例):8B fp16 batch 12 → 10 卡 5.2 万;8B int4 batch 36 → 6 卡 4.3 万;32B int4 batch 5 → 29 卡 9.3 万。不用于银行生产:24 GB 限制 batch、不能高效多卡拆分、GeForce 驱动许可禁止数据中心部署 + 出口管制、无 ECC 不适合 7×24。适合开发测试、PoC、小团队、QLoRA 微调。

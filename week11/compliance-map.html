一个请求的一生:合规控制放在哪一站

场景:乙银行员工 li 在你的"银行客服 Agent"里问:"客户王小明卡号 6222…445 丢了,帮我挂失。"这个请求从进门到出门要经过 8 站,每一站都有一个合规控制。点每一站,或者用"下一站"按钮走一遍。

一句话记住

合规 = 每一站都能回答三个问题:数据去哪了(不出域)、谁能看(租户隔离、权限)、出事能不能查(审计)。
凡是"必须做到"的,都放在代码 / 数据库 / 网络里强制;prompt 只做"锦上添花"。

常被问到的法规和要求(概念级,做方案时以原文和客户合规部门为准)

名字大白话落到方案里
网络安全法 → 等级保护 2.0(等保)系统按重要程度定级,定级后要测评金融、政务的核心系统常要求三级;部署环境、日志、访问控制都要过测评
数据安全法数据要分类分级,重要数据重点保护先给客户数据定级:哪些能进模型、哪些只能本地处理
个人信息保护法个人信息要最小必要、告知同意;身份证、金融账户属于敏感个人信息第 2 站脱敏、第 8 站日志脱敏;交给第三方(如公网 API)处理要有依据
生成式人工智能服务管理暂行办法(2023)面向公众提供生成式 AI 服务,要做安全评估、备案,管好生成内容第 2、7 站内容安全;对公众的产品要用已备案的模型 / 服务
数据出境相关规定重要数据、大量个人信息出境要评估境外模型 API = 数据出境,大多数国内金融 / 政务客户直接排除

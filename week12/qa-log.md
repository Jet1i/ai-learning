# 第 12 周 提问记录

## 22:58 VLM 就是多模态吗？CLIP 呢？
- 多模态 = 大类(文字/图片/语音/视频不止一种)。
- VLM = 视觉语言模型，输入图 + 文，输出文字(GPT-4o、Qwen-VL)。
- CLIP = 图片和文字各变一个向量、算相似度，不会生成。类比：bge ↔ CLIP(只出向量);DeepSeek ↔ VLM(能生成)。
- 很多 VLM 的"眼睛"就是 CLIP 的图片编码器(LLaVA = CLIP ViT + 投影层 + LLaMA)。

## 22:59 DeepSeek 实现不了 VLM 吗？加个 CLIP 插件呢？
- DeepSeek 发布过 VL2、OCR 等开源视觉模型;deepseek-chat API(据我所知)只收文字。
- 做法 1 外挂工具：图 → OCR/小 VLM → 文字 → LLM。不能直接挂 CLIP(输出是向量，LLM 读不了;只能在候选标签里挑)。丢版面信息，但便宜。
- 做法 2 接进模型(LLaVA):CLIP 编码器 → 投影层 wx+b(要训练，因为两边维度和含义不同)→ 塞进 LLM 输入。需要开源权重，API 做不了。
- 售前：抽字段先 OCR + 文字 LLM;要看懂版面/图表再上 VLM。

## 23:14 CLIP 现在还有人用吗？
- 原版少用，后代大量用:SigLIP 等对比学习编码器是很多 VLM 的"眼睛"(LLaVA 系列、PaliGemma)。
- 以图搜图/以文搜图、多模态 RAG(图片向量进向量库)。
- 文生图(Stable Diffusion 用 CLIP 文字编码器)。
- 零样本打标签、内容审核、训练数据清洗(CLIP 分数)。中文用 Chinese-CLIP。
- 售前：搜图/分类/审核 → CLIP 类;看懂并回答 → VLM。

## 23:25 路由只能把一句话的多个要求派给一个 Agent 吗？
- 不是，是代码让它只输出一个 category。路由 = 分诊台，单意图时快又便宜。
- 多意图修法:①路由输出任务列表(= 编排者，要汇总);②专员之间 handoff(OpenAI Agents SDK),链条变长;③专员办完回到路由再派。
- 交接只传摘要的坑和结构无关：交接要传原话 + 结构化字段。

## 23:26 多 Agent 的 orch 会把调用过程写死吗？
- 会。run_orch 写死：拆→派→汇总三步、顺序执行、专员列表和工具权限、max_steps;模型决定：拆几个、归类、字段、专员内部调哪个工具、措辞。
- 光谱：全写死工作流(稳定好测好审计)↔ 全自主 Agent(灵活难预测)。流程固定/出错代价大 → 写死;规则写不完 → 交给模型。
- 银行例子：冻结前核验身份写死在代码(同 guard 思路)。参考 Anthropic《Building effective agents》。

## 23:32 精读 Anthropic《Building effective agents》(2024-12-19,Erik S. & Barry Zhang)
- 主旨：最成功的团队用简单可组合的模式，不用复杂框架;只在效果确实变好时加复杂度。
- 工作流(代码预定路径)vs Agent(模型自己决定步骤)。积木 = 增强型 LLM(检索 + 工具 + 记忆)。
- 模式：提示链(中间代码 gate)、路由、并行(分段 sectioning / 投票 voting)、编排者-工人(子任务按输入现拆)、评估-优化循环;Agent = LLM 在循环里根据环境反馈用工具。风险：成本高、错误累积。
- 框架：先直接用 API;用框架要懂底层。
- 三原则：简单、透明(展示计划)、认真设计 ACI(工具文档 + 测试 + 防呆，如强制绝对路径)。
- 附录：客服、编程最适合 Agent(结果可验证、有反馈)。
- 练习：客服适合 Agent vs "默认单 Agent" 矛盾吗;freeze_card 防呆;合规检查选并行还是评估-优化。

## 00:02 Agent SDK 是什么？
- = 把第 4 周手写的 while 循环(调模型→执行工具→结果塞回→再调)打包好的库;另带工具 schema 自动生成、MCP、handoff、护栏、追踪。
- OpenAI Agents SDK(2025 初，轻量);Claude Agent SDK(原 Claude Code SDK,带文件/命令/MCP/上下文压缩/子 Agent);Google ADK、AWS Strands。
- 基本就是可复用的 harness。简单流程手写最透明;要追踪/交接/护栏用 SDK,注意厂商绑定。

## 00:16 OpenAI《research acceleration: jagged frontier》(无日期，数据截至 2026-10-18)
- Jagged = Agent 能力像锯齿，按任务类别差别很大。
- 无人干预成功率：2-4h 任务 23%→46%,4-8h 13%→35%(3 月→10 月);沟通 69% / 分析 58% / 构建 43%;盯训练 79%、写推理服务代码 25%。

- 文章自认坑：成功率上涨部分来自任务构成变化(人挑 Agent 擅长的);问卷自报。

## 00:21 SLA 是什么？
- 服务等级协议，写进合同的承诺(可用性、P95 延迟等),做不到要赔。建议写 P95/P99 + 超时比例，不写平均值。
- 灰度 0.1%(20 条投诉/天)模拟：真变差时漏报 11%,没变时误报 33% → 样本太少不可信。

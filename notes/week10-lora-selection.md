# 第 10 周：LoRA 实操、合并与 QLoRA、Prompt / RAG / 微调选型

日期：2026-11-16（一晚）· 代码：`week10/` · 周测：约 2.8/5

## 一句话总结
微调本来要改每个大矩阵 W 的全部数字。**LoRA** 把 W 冻住，旁边学一个低秩补丁 **ΔW = B·A**（r 很小），只训 0.1%～0.3% 的参数：**存储**按 MB 算、**训练显存**省掉梯度和 Adam（7B：112 GB → 约 18 GB）、**一个底座能挂很多补丁**。但 LoRA 不会自动防遗忘，**遗忘是数据问题**，要混旧数据（replay）；学习率要比全参大 10～20 倍。训完可以**合并**成普通模型（延迟最低，但拔不下来）；**QLoRA** 把底座压成 4 bit 再挂 LoRA，70B 也能在一张大卡上微调。选型的核心：**Prompt 改输入、RAG 自动改输入（知识在外面）、微调改权重（行为练进去）**——缺知识用 RAG，缺行为用微调，永远先试 Prompt。

## 核心概念

### 1. LoRA 原理（lora.py）
- 模型变成 **y = x·W + x·(B·A)·s**，W 冻住；A 是 r×d_in，B 是 d_out×r，s = alpha / r。
- 最小例子：4×4 的 B·A（r=1）= 一列 × 一行，8 个数表示 16 个数，每一行都是 A 的倍数。
- **x·Aᵀ**：A 的 r 行 = 补丁"读"哪 r 个方向（768 维压成 r 个数）；**再乘 Bᵀ**：B 的 r 列 = 往哪 r 个方向"写"。方向不是人定的，是梯度下降学出来的，趋近目标改动 SVD 最大的 r 个方向。
- **B 初始化为 0、A 随机**：训练第 0 步模型和原来完全一样（输出差 0.000000）；A 随机保证梯度不为 0。A、B 都为 0 → 两者梯度互相乘着对方 → 永远是 0。
- **r 够不够**：要学的改动只有 4 个方向（TRUE_RANK=4）时 r=4 误差就降到 0.0008（全量 ΔW 589,824 参数，LoRA r=4 只要 6,144）；改动有 768 个方向时 r=16 几乎无效。r=384 时 LoRA 参数已等于全量 ΔW，没有意义。
- 实际：话术、格式、几类问答 → r=8～16 够；新语言、大量新知识 → 先试 64～128，不够就全参。
- 真实模型：GPT-2 每层 c_attn 挂 r=8 → 294,912 参数（0.24%）；LLaMA-2 7B 给 q、v 挂 r=16 → 8,388,608（0.12%）。

### 2. LoRA 实操（lora_sft.py）：两个坑
- **坑 1 学习率**：从全参抄的 LR 5e-5 → LoRA 10 轮 loss 还是 4.92，新业务 0/4（补丁 B 几乎还是 0）。全参 1.24 亿参数各挪一小步合起来影响大；LoRA 只有 29 万参数且从 0 出发。**LoRA LR 通常是全参的 10～20 倍**（大模型 1e-4～2e-4，这里 1e-3）。
- **坑 2 遗忘**：LR 1e-3 只训新数据 → 新业务 2/4、旧问题 0/6，旧问题都答成 "Open My Orders and tap Warranty Claim. Gift cards never expire."。补丁对**所有输入**都生效，loss 里没有"旧的也要答对" → **W 没变 ≠ 行为没变**。全参也一样（灾难性遗忘）。
- **修法 replay**：每类旧问题混 2 条（REPLAY=2）→ 新业务 3/4、旧问题 4～5/6。
- 测试集只有 6 题，1 题 = 17%，4/6 和 5/6 算同一水平；Mac 和云端的浮点差异就能翻转一题。

### 3. 为什么 LoRA 省：同一个原因 —— W 不变，变化全在 A、B
- **存储**：7B 全参每个品牌 13.5 GB；LoRA 每个品牌 17 MB。10 个品牌 135 GB vs 13.7 GB。
- **训练显存**：每个**可训练**参数 16 字节（权重 2 + 梯度 2 + Adam m、v 各 4 + fp32 主权重 4）。LoRA 的 W 只要权重 2 字节，省的是梯度 + Adam。
- **速度不会快几百倍**：反向传播还要穿过整个模型（第 1 层的 LoRA 也要梯度），只省掉"算 W 自己的梯度"，实测 14 s vs 38 s（约 2.7 倍）。
- **换补丁**：`disable_adapter()` 拔掉就回到原模型；上线一份底座 + N 个补丁，vLLM multi-LoRA 能把不同品牌的请求放进同一个 batch。

### 4. 合并与 QLoRA（merge_qlora.py）
- **合并**：x·W + x·(s·B·A) = x·(W + s·B·A)（乘法分配律）→ W' = W + s·B·A，扔掉 A、B。logits 差 0.000046（浮点舍入）。合并后不多算 x·A·B，延迟最低，但补丁焊死、又是完整模型。
- 一个品牌、要低延迟 → 合并；多个品牌 → 不合并（显存按 1 个模型算，能合批）。
- **QLoRA**：底座分组量化成 4 bit（NF4，每 64 个数共用缩放）并冻住；前向时临时解压回 bf16 算 x·W，再加 x·A·B（bf16）；梯度穿过解压后的 W 传给 A、B。bitsandbytes 只能在 NVIDIA GPU 上跑。
- **两种压缩别混**：少存几个数（低秩：MLA 的 c、LoRA 的 B·A）vs 每个数少用几位（量化：第 7 周 int4、QLoRA 的 Q）。
- QLoRA 损失来自 W 的 4 bit 舍入；合并进 4 bit 底座要再量化一次，刻度可能比补丁（|B| 平均 0.009）还大 → 合并进 fp16，要压缩就合并后再量化并重新评测。

### 5. Prompt / RAG / 微调 选型
类比新员工：Prompt = 每次给张便利贴；RAG = 给一本手册自己查；微调 = 送去培训养成习惯。

| | Prompt | RAG | 微调（LoRA） |
|---|---|---|---|
| 改的是 | 输入 | 输入（自动检索） | 权重 |
| 适合 | 简单要求、快速验证 | 会变的知识、要出处 | 格式、风格、行为、术语 |
| 知识更新 | 改 prompt | 改文档，立刻生效 | 重新训练 |
| 需要数据 | 几个例子 | 文档 | 几百～几千条标注 |
| 上线时间 | 小时 | 天～周 | 周 |
| 每次调用成本 | prompt 越长越贵 | 多一次检索 + 更长输入 | prompt 短，可换小模型 |
| 主要风险 | 不稳定 | 检索不到 → 答错 | 遗忘、过拟合、知识过时 |

规则：① 永远先试 Prompt；② 缺知识 → RAG（结构化数据如价格表 → 直接工具调用查库）；③ 缺行为 → 微调；④ 常组合：RAG 管"知道什么"，微调管"怎么说"。每个方案都先想一个更便宜的先手（JSON Schema 约束解码、术语表 RAG、prompt caching）。

## 我的提问与解答
详见 [week10/qa-log.md](../week10/qa-log.md)。要点：
- TRUE_RANK=768 改的是"要学的改动有几个方向"，不是 LoRA；r 是补丁能改几个方向。
- 16 个方向是梯度下降学出来的（A 读、B 写）。
- 默认 0/4 是学习率太小；2/4、0/6 是只用新数据导致遗忘，不是学习率太大。
- REPLAY 后"比训练前还好"：混了旧数据复习，但 6 题测试集差 1 题算噪声。
- LoRA 的三个优势都来自"W 不变"。
- QLoRA 的压缩是量化，不是 MLA 那种降维。

## 易错点
- 只写结论不写机制（热身 GRPO 题：要说 A = 1 − 1 = 0 → 梯度 0）。
- 以为 LoRA 训练快几百倍：只快约 1.3～3 倍，省的是显存（梯度 + Adam），不是计算。
- 以为冻住 W 就不会遗忘：补丁对所有输入生效，遗忘靠数据混合解决。
- LoRA 学习率直接抄全参。
- 把量化（每个数少几位）和低秩（少存几个数）混为一谈。
- 选型题只给选择，不给理由和风险。
- 以为全参微调能解决遗忘：全参只训新数据同样 0/6。
- 判断瓶颈只看一次 loss：要控制变量，先固定 r 扫 LR，再用最佳 LR 扫 r。看曲线：LR 太小 = 慢慢降没到底；LR 太大 = 乱跳/NaN；r 不够 = 停在地板上，r 越大地板越低。
- 多租户不合并的理由：是显存/存储 ×N 和能合批，不是"改了要重训"。

## 小测
1. **只训法律数据的 LoRA 让什么都带法律腔**（0.4）：补丁对所有输入生效，loss 只有法律数据 → 遗忘。修法：混旧数据；降 LR / 少训 + 通用测试集早停；不合并、按问题路由（非法律问题 disable_adapter）。全参不是修法。
2. **越南语 r=8 loss 降不下去**（0.4）：控制变量实验——同 LR 同数据扫 r=8/32/128，再固定 r 扫 LR。r 越大越好 → 秩瓶颈；LR 敏感 → 学习率；都不行 → 数据。r=128 还不行才考虑全参或继续预训练。
3. **50 个租户各要语气**（0.5）：一份底座 + 50 个 LoRA、不合并。理由：合并 = 50 个完整模型（×50 显存存储），不合并能 multi-LoRA 合批。风险：路由挂错补丁（租户隔离）、每租户要有评测集。
4. **QLoRA 合并后再量化 4 bit 变差**（0.6）：补丁是针对 4 bit 底座学的；W + s·B·A 再舍入，刻度可能比补丁大 → 补丁被舍掉。建议：4 bit 底座 + 不合并补丁直接部署（和训练一致）；或合并进 fp16 后用 GPTQ/AWQ 校准量化并重新评测。
5. **每月更新的手册 + 固定三段格式**（0.9）：RAG 管知识、LoRA 管格式；7B LoRA 约 18～20 GB，一张 4090。加分：训练样本里带上检索段落，让格式在真实长上下文下也稳定。

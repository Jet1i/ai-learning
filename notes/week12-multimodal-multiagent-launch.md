# 第 12 周：多模态、多 Agent、上线监控与客户版方案

日期：2026-11-19 晚 ～ 11-20 · 代码：`week12/` · 周测：约 2.5/5（第 11 周 1.7）

## 一句话总结
**VLM** = 视觉编码器（图切块 → 每块做一次 wx+b 变成 token）+ 普通 LLM，图片 token 和文字 token 排在同一个序列里；成本和延迟主要看**分辨率**（一张高清 A4 约 3000 token）。**CLIP** 只把图和字各变成一个向量算相似度，不会生成，适合搜图、分类；要读懂、抽字段用 VLM，要逐字精确就用 OCR + 代码比对。**多 Agent** 默认不拆：每多一个环节就多一个出错点（0.9³ ≈ 73%，0.9⁵ ≈ 59%），只有权限隔离、工具太多、需要并行时才拆，交接要传原话 + 结构化字段。**上线**有三道关：上线前黄金测试集回归、上线时灰度（样本要够）、上线后看 P95/P99 和**分类别**指标，平均值和总体指标都会骗人。**客户版方案书**：结论放最前、说业务话、每个数字带依据和假设、最后写下一步和需要客户做什么，**不承诺模型不犯错**。

## 核心概念

### 1. 图片怎么变成 token（vlm1.py）
- 4×4 小图、2×2 切块 → 4 块，每块拉平 4 个数 → `patches @ W + b` → 4 个 d 维「图片 token」→ 和文字 token 拼成一个序列，送进第 3 周的 Transformer。
- 颜色一样的两块得到完全相同的向量 → **必须加位置编码**，否则「棋盘」和「上黑下白」、数字「12」和「21」分不清。
- 真实规模（patch 14，2×2 合并成 1 个 token）：224² → 64，448² → 256，1024² → 1332，1344×1792 → 3072 个 token。
- token 数 ∝ 分辨率的平方；去掉 2×2 合并 token 变 **4 倍**：小字更清楚，但成本和延迟约 4 倍。
- 售前：先问图多大、一次几张、能否裁剪；5 万张高清扫描件/天 ≈ 1.5 亿 token/天，按 2 元/百万估约 300 元/天，**真正的坑通常是合规（保单不出域）和准确率（手写、盖章），不是成本**。

### 2. CLIP（clip1.py）
- 两个编码器，各出一个 512 维向量；对比学习：配对的图文靠近、不配对的推远。类比：bge ↔ CLIP（只出向量），DeepSeek ↔ VLM（能生成）。
- 实验：英文描述 3/3 认对，概率 0.99；**中文描述**绿三角认成蓝方，概率平摊在 0.2～0.39（CLIP 几乎只用英文训练）→ 中文用 Chinese-CLIP。
- 原始余弦相似度都在 0.2～0.3，softmax 前**乘以 100**（学出来的 logit_scale，相当于温度 0.01）：差 0.054 → 乘 100 后差 5.4 → e^5.4 ≈ 220 倍。这不是生成时的采样温度。
- 用途：VLM 的「眼睛」（SigLIP 等后代）、以图搜图 / 多模态 RAG、文生图的文字编码器、零样本打标签和审核。
- 「DeepSeek + CLIP 插件」：外挂只能挂 OCR / 小 VLM 转成文字（丢版面）；真正接进模型要训练投影层（LLaVA），必须用开源权重，API 做不了。

### 3. 多 Agent（multi_agent.py）
| 写法 | 结构 | 结果（用户一句话两件事） | 调用模型 |
|---|---|---|---|
| single | 一个 Agent，4 个工具 | 冻卡 + 理财都办了 | 2 次 |
| router | 路由选**一个**专员，交接只传摘要 | 理财丢了；摘要漏尾号则专员只能反问 | 2 次 |
| orch | 编排者拆子任务 → 多个专员 → 汇总 | 都办了 | 6 次 |
- 默认单 Agent。必须拆的情况：**权限隔离**（读外部文档的 Agent 不给发送工具，致命三要素凑不齐）、工具太多选错、需要并行（子任务独立时）、不同环节用不同模型。
- 串联出错累积：0.9³ ≈ 73%。交接处加校验，交接传**原话 + 结构化字段**。
- 写死 vs 交给模型：流程固定、出错代价大的写死（冻卡前核验身份）；规则写不完的交给模型（判断这句话说的是什么事）。

### 4. 《Building effective agents》（Anthropic，2024-12-19）
- 工作流（代码预定路径）vs Agent（模型自己决定步骤）；积木 = 增强型 LLM（检索 + 工具 + 记忆）。
- 模式：提示链、路由、并行（分段 / 投票）、编排者-工人（子任务按输入现拆）、评估-优化循环；Agent = LLM 在循环里根据环境反馈用工具。
- 先直接用 API，用框架要懂底层；三原则：简单、透明、认真设计 ACI（工具说明 + 测试 + **防呆**：如强制绝对路径；冻卡改成只能从 `list_my_cards()` 里选）。
- Agent SDK = 把第 4 周手写的 while 循环打包好的库（OpenAI Agents SDK、Claude Agent SDK 等），自带 handoff、护栏、追踪。

### 5. 上线：监控、灰度、回归（monitor.py）
- **平均值骗人**：平均首字 0.99 秒，P50 0.62，P95 4.30，**P99 10.59 秒**；超过 3 秒 5.2%，每天 20 万请求就是 1 万人在等。SLA 写 P95/P99 + 超时比例。
- **总体指标骗人**：v2 总体转人工 7.5% → 7.8%，但投诉类 8% → 29%；查余额（占 40% 流量）变好约 5 个点，盖住了投诉（占 10%）变差约 21 个点。
- **灰度样本要够**：0.1% 流量每天只有约 20 条投诉，模拟一万次：真变差时漏报 11%，没变时误报 33%。灰度比例 = 风险 vs 发现速度的取舍。
- **黄金测试集**挡已知问题（不能有「原来对、现在错」）；方言错别字、真实并发、新产品、攻击试探、成本失控只有线上才暴露。
- OpenAI「jagged frontier」：Agent 无人干预成功率按类别差很多（沟通 69% / 分析 58% / 构建 43%），总分会盖住弱项；成功率上涨部分来自「人挑 Agent 擅长的任务」。

### 6. 客户版方案书
- 读者是行长、科技部、业务负责人，只花 3 分钟：解决什么、多少钱、什么风险、下一步要我做什么。
- 4 个区别：结论最前（一页纸摘要）、业务话（技术放附录）、数字带依据和假设、结尾写下一步和客户配合事项。
- 例：「32B int8 单张 H200，开前缀缓存月成本约 14 万」→「整套系统部署在贵行自己的云环境里，数据不出行；按每天 20 万次咨询估算，每月约 14～17 万元，每通约 1 毛钱。」

## 我的提问与解答
（完整记录见 `week12/qa-log.md`）
- **VLM 就是多模态吗？CLIP 呢？** 多模态是大类；VLM 输入图文、输出文字；CLIP 只出向量算相似度。很多 VLM 的眼睛是 CLIP 式编码器。
- **DeepSeek 实现不了 VLM？加个 CLIP 插件呢？** DeepSeek 有开源视觉模型，但 deepseek-chat API 只收文字；外挂只能转成文字，真接进去要训投影层、用开源权重。
- **CLIP 现在还有人用吗？** 后代 SigLIP 等大量用：VLM 编码器、搜图、多模态 RAG、文生图、审核。
- **路由只能把多个要求派给一个 Agent 吗？** 不是，是代码只给了一个格子；修法：输出任务列表（编排者）、handoff、办完回到路由。交接只传摘要的坑和结构无关。
- **orch 会把调用过程写死吗？** 会，骨架写死、细节交给模型；工作流 ↔ 自主 Agent 是一条光谱。
- **那篇文章什么时候发的？很火吗？** 2024-12-19；Agent 工程圈引用最多的入门文章之一。
- **Agent SDK 是什么？** 打包好的 Agent 循环 + handoff / 护栏 / 追踪，基本就是可复用的 harness。
- **OpenAI 按任务类别评 Agent？** jagged frontier：能力像锯齿，按类别评，总分盖住弱项。
- **SLA 是什么？** 写进合同的服务承诺（可用性、P95 延迟），做不到要赔。

## 易错点
1. **结论没有依据**（贯穿全周）：「很安全」「GPU 利用率高」「按业务测试」→ 每句跟上机制、数字或例子。
2. 混淆 CLIP 的 logit_scale（×100 放大差距）和生成时的采样温度；以为 CLIP 能「描述图片」。
3. 去掉 2×2 合并是 4 倍不是 2 倍；0.9³、0.9⁵ 要算到最后的数（73%、59%）。
4. 合规检查查的是**回答**，只能放在回答之后。
5. 格式校验 ≠ 防呆：格式对的卡号也可能是别人的卡；防呆是让模型根本没法填错（只能从本人卡列表里选）。
6. 小样本灰度不可靠：几十条样本时随机波动比真实差异还大。
7. 客户话禁忌：说绝对的话（「不会犯错」「很安全」）；承诺模型不犯错 → 应说「理解错了也办不成」。
8. 「能裁多少坐席」：40% 是通话量目标，不等于 40% 工时（简单通话短）；售前给数据，人员去留由客户决定。

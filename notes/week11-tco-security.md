# 第 11 周：成本 TCO、云上部署选型与安全合规

日期：2026-11-16 ～ 11-19（四个晚上）· 代码：`week11/` · 周测：约 1.7/5

## 一句话总结
售前的两本账：**钱**和**安全**。API 按 token 收钱，输入、输出、缓存命中分开计价，大头往往是**输入**（RAG 段落），省钱先靠**前缀缓存**和**砍输入**。自建按卡时收钱，不管用没用：成本 = ⌈高峰 ÷ 每卡能力⌉ × 卡价 + 运维，**利用率和高可用下限**决定了自建贵不贵。和 DeepSeek API 比，自建在哪个量级都没赢过；和旗舰 API 比，量大才赢。很多客户私有化的真正理由是**合规**，不是省钱。上云分 4 层（MaaS / PaaS / IaaS / 私有化），先问「数据能去哪」定下限。安全的核心原则：**模型只能提议，执行权在代码**。Prompt 防护只能降低概率；白名单、人工确认、租户过滤、审计日志都要写在代码、数据库和网络层。

## 核心概念

### 1. API 账本（tco_api.py）
- 三种价：输入命中 / 输入未命中 / 输出。DeepSeek 示例 0.2 / 2 / 3 元每百万 token（以官网为准）。
- 一次客服请求：系统提示 1500 + RAG 2000 + 用户 100 = 输入 3600，输出 300 → 约 0.8 分钱。每天 100 万次：DeepSeek 约 24 万/月，旗舰约 335 万/月。
- **大头是输入**：token 数差 12 倍，盖过了 1.5～5 倍的单价差 → 先砍 RAG 段落（少取几段、rerank、切短）。
- **前缀缓存**：同样的开头不用再算 prefill，便宜 10 倍；按前缀匹配，**第一个 token 一变，后面全部失效** → 会变的内容（时间、用户名）放到最后。
- **多轮对话**：API 无状态，每轮都要重发历史，10 轮比天真估算贵 1.9 倍 → 截断或总结历史；历史本身也是前缀，能命中缓存。
- **输出为什么贵**：decode 每出 1 个 token 都要读一遍全部权重（显存带宽瓶颈）；prefill 几千个 token 一起算，算力吃满。

### 2. 自建账本（tco_gpu.py）
- 每卡能力（roofline 粗估 × 效率 0.4）：
  - decode 一步 = 读「权重 + 这一批的 KV cache」÷ 带宽，一步出 batch 个 token
  - prefill = 算力 ÷（2 × 激活参数）
  - 每次请求占卡时间 = 输入 ÷ prefill 速度 + 输出 ÷ decode 速度
- 月成本 = ⌈高峰请求/秒 ÷ 每卡请求/秒⌉ × 卡时价 × 720 + 运维（至少 2 套做高可用）。
- 8B @ A100（客服场景，100 万次/天）：prefill 0.46 秒 > decode 0.27 秒（**合批之后 decode 被分摊，长输入让 prefill 成了大头**）；16 卡，利用率 53%，31.8 万/月 vs DeepSeek API 24 万。
- **故意的错**：假设 24 小时满载。真实流量高峰是平均的 1.9 倍，机器要按高峰租。
- 盈亏平衡：和 DeepSeek API 比，自建一直没赢；和旗舰 API 比，自建 V3 在约 20 万次/天以上开始便宜。
- **私有化只能按峰值买**：云上弹性一天 214 卡时（利用率约 95%），买断要 16 × 24 = 384 卡时（53%）；补救：削峰（排队）+ 填谷（夜间跑批）。
- **batch 怎么定**：① 显存上限（80 − 16 − 4 GB ÷ 0.48 GB/请求 ≈ 125）；② 吞吐边际递减（batch 1/16/64/125 → 121/1350/2740/3290 tok/s，权重能分摊，KV 不能）；③ 每个用户的速度（121/84/43/26 tok/s）。

### 3. 硬件基础（Jet 的提问）
- **显存 ≠ SSD**：SSD 是存储（TB 级、几 GB/s，放模型文件）；显存是 GPU 卡上自带的内存（HBM，80～141 GB、2～4.8 TB/s）。启动时模型一次性搬进显存，之后每个 token 只读显存：8B 16 GB ÷ 2 TB/s = 8 ms，若从 SSD 读要约 2.3 秒。Mac M 系列是统一内存。
- **每 token 的 KV**：LLaMA-3 8B = 2 × 32 层 × 8 个 KV 头 × 128 维 × 2 字节 = 128 KB；没有 GQA 时是 512 KB。
- **选卡看每次请求的成本，不看单卡价格**：显存是门槛 → decode 看带宽、prefill 看算力 → 多卡看 NVLink → 买不买得到（出口管制、信创国产卡）。

| 卡（32B int8，银行场景，卡价为示例） | 显存 / 带宽 / 算力 | 每卡请求/秒 | 每次 | 月成本 |
|---|---|---|---|---|
| A100 80G | 80 GB / 2.0 TB/s / 312 T | 0.40 | 1.7 分 | 22.8 万 |
| H20 | 96 GB / 4.0 TB/s / 148 T | 0.24 | 3.5 分 | 41.9 万 |
| H200 | 141 GB / 4.8 TB/s / 989 T | 1.23 | 1.1 分 | 17.4 万 |
| RTX 4090（32B int4） | 24 GB / 1.0 TB/s / ~165 T | 0.15 | 0.6 分 | 9.3 万（29 卡） |

最贵的卡反而最省；H20 算力弱，长输入场景最差；4090 单卡便宜，但显存小、没 NVLink、驱动许可禁止数据中心部署，只适合开发和 PoC。

### 4. 云上 4 层（cloud-map.html）
| 层 | 付费 | 数据在哪 | 适合 |
|---|---|---|---|
| MaaS（百炼、方舟、Bedrock） | 按 token | 厂商 | PoC、量波动大 |
| PaaS（PAI-EAS、SageMaker） | 按实例时长 | 客户云账号 | 自己的模型、多 LoRA |
| IaaS（GPU 云服务器） | 按卡时 | 客户云账号 | 量大且稳、要调优 |
| 私有化 | 采购 + 折旧 | 客户机房 | 涉密、物理隔离 |

数据位置 5 档：公网 API → 私网接入（只保护路上那段，数据仍在厂商处理）→ 专属实例（GPU 独占，但在厂商账号里）→ 客户 VPC（客户自己云账号里的私有网络，硬件仍在厂商机房）→ 本地机房。先问三件事：数据能去哪、量多大稳不稳、要不要自己的模型。

### 5. Prompt 注入（inject.py）
- 间接注入：Agent 读的文档、网页、邮件里藏指令。模型分不清，因为系统提示、用户的话、工具结果都是**同一串 token**。
- 实测 DeepSeek：v1（明显的系统通知）、v2（伪装成折扣流程）、v3（v2 + 用户授权）全是 0/3。说明新模型能识破这几种写法，但 9 次 ≠ 永远安全。
- 假模型（一定会被骗）：naive 3/3 泄露、prompt 3/3、**guard 0/3**。
- guard = `run_tool()` 里的普通 if：收件域名白名单 + 读过外部内容后发邮件要用户确认。**模型只能提议，执行权在代码。**
- 致命三要素：私密数据 + 不可信内容 + 外发通道，去掉一个就切断泄露链。
- 绕过白名单的出口：内部邮箱自动转发、Markdown 图片 URL 带数据、网页工具、共享文档 → 所有出口都要管 + DLP。
- 人工确认不能做成 tool（模型被骗可以跳过），要写在 agent 循环里；网页系统把「待确认动作」存数据库，用户点按钮后再续跑（LangGraph interrupt）。
- 澄清（质量问题，模型判断即可）vs 审批（安全问题，必须代码）：标准是漏掉的后果能不能接受。

### 6. 合规地图（compliance.py + compliance-map.html）
- 一个请求 8 站：进门（认证、租户来自登录会话）→ 输入检查（内容安全、脱敏）→ 检索（**先按租户/权限过滤，再打分**）→ 拼提示词（不可信标签）→ 模型推理（数据位置、不留存、前缀缓存按租户隔离）→ 工具调用（白名单、审批）→ 输出检查（再扫描、拦外部链接）→ 记录（审计日志）。
- 租户隔离的两个漏洞：租户由用户自己声明；后过滤（别家文档先进候选，本租户可能被挤出 top-k）。
- 脱敏：正则只能抓固定格式（手机号、身份证、卡号，记得加数字边界），抓不到名字、地址、换说法、商业机密 → 业务数据整体不能出域时必须私有化。
- 共享前缀缓存 = **时间侧信道**：命中更快，能试探别家发过的内容 → 缓存 key 带租户 ID。
- 审计日志存脱敏后的问题和文档 ID；原文加密单独存，查看本身也要记日志。
- 法规（概念级）：等保 2.0、数据安全法、个人信息保护法、生成式 AI 服务管理暂行办法、数据出境。

## 易错点
- 只写结论不写依据和数字（周测五题都是这个问题）。
- prefill 选卡看**算力**，decode 看**带宽**，别反过来。
- 以为私有化能提高利用率：恰恰相反，只能按峰值买。
- 「自建一定便宜」：要说清楚**跟谁比**（DeepSeek API 还是旗舰 API）、什么量级、利用率多少。
- 前缀缓存对自部署不省钱、省的是算力，只有让卡数降下来才省钱；被高可用下限卡住时完全不变。
- 私网接入 ≠ 合规：只保护传输，数据仍在厂商处理。
- 致命三要素里最容易漏的是**不可信内容**（用户输入本身、外部文件）。
- 输入过滤是防线不是来源；输入检查要做成独立模块，不是写在 prompt 里。
- 「可审计」是要求，不是能量化的指标。
- 共享缓存的风险是时间侧信道，不是「回答路由错」。

## 小测
1. **律所 5 万次/天、输入 6000/输出 200，自建 8B 划算吗**（0.3）：prefill 0.77 秒 vs decode 0.18 秒 → 选算力强的卡；高可用 2 卡 + 运维 ≈ 6.6 万/月 vs DeepSeek API ≈ 1.9 万；钱花在固定成本。建议先用 API，除非合规要求或量涨上来。
2. **系统提示开头加了用户名和日期，账单涨了**（0.6）：前缀第一个 token 变了，后面 1500 token 全部不命中；变量移到最后；vLLM 也受影响，前缀缓存失效 → 每卡能力下降 → 可能多租卡。
3. **三个客户选层**（0.5）：初创 → MaaS（风险：限流、涨价）；保险 → 客户 VPC + multi-LoRA（风险：固定成本、补丁路由）；军工 → 私有化（风险：按峰值买、升级慢）。
4. **HR 助手三要素**（0.3）：员工档案 / 候选人 PDF 简历 / 发邮件；代码层：读简历的 agent 不给档案权限、邮件固定模板 + DLP、读外部简历后发邮件要 HR 确认；prompt 和攻击文本在同一串 token 里，只能降概率。
5. **租户串数据**（0）：租户来自用户声明 → 从登录会话取；后过滤或没过滤 → 查询时带租户条件或独立索引；加分：共享前缀缓存 → key 带租户。

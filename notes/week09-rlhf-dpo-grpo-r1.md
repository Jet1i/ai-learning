# 第 9 周：SFT、奖励模型、RLHF/PPO、DPO、GRPO 与 DeepSeek-R1

日期：2026-11-13 ～ 11-15（分三晚）· 代码：`week9/` · 周测：约 2.7/5

## 一句话总结
预训练模型只会续写。**SFT** 教它照着示范回答；想让它"更好"而不只是"像示范"，就要一个打分的东西：**奖励模型**（人类偏好学出来的裁判）或者**规则**（答案对不对）。**PPO** 用裁判分数 + KL 绳子 + 价值模型分功劳 + clip 去改模型，要 4 个模型，很贵；**DPO** 把裁判藏进"概率比 SFT 模型涨了多少"，只用偏好对离线训练；**GRPO** 去掉价值模型，一题采一组、组内比高低。**DeepSeek-R1** 就是把这几样按顺序拼起来：冷启动 SFT → GRPO（规则奖励）→ 拒绝采样再 SFT → 全场景 RL，最后蒸馏给小模型。

## 核心概念

### 0. SFT：照着示范学（sft.py）
- 数据是"问题 + 人写的回答"。loss = 回答部分每个 token 的 **−ln p(人写的 token)** 取平均。每个 token 权重都是 1，永远往上推。
- **问题部分 label = −100**：PyTorch 交叉熵的 ignore_index，这些位置不算 loss，模型只学"怎么答"，不学"怎么问"。
- 求平均而不是求和：回答长短不一，平均后 loss 的大小和学习率不随长度变。e^(−loss) ≈ 每个 token 的典型概率。
- 加特殊 token（`<|user|>` `<|assistant|>` `<|end|>`）要 resize 词表 50257 → 50260，新行用旧 embedding 的均值初始化（mean_resizing）。
- **答完会停**也是学出来的：`<|end|>` 也是一个要预测的 token。5 轮时没学会，回答停不下来；10 轮才好一些。
- 全参数 SFT 显存：7B × 16 字节（fp16 权重 2 + 梯度 2 + Adam 12）= **112 GB**。LoRA 只训一小部分参数，省的是梯度和 Adam 那部分。

### 1. 奖励模型：从"哪个更好"学出一个分数（reward.py）
- 结构：SFT 模型 + 一个 Linear(768 → 1)，读**最后一个 token** 的向量出一个分数。
- 数据：同一个问题两个回答，标注员（真人）选哪个更好。loss = **−ln σ(r_chosen − r_rejected)**（Bradley-Terry），只关心分差，所以分数整体加一个常数没影响（b 学不出来）。
- 实际做法：一个问题让标注员给 K = 4～9 个回答排序，拆成 C(K,2) 对。
- **奖励模型会被钻空子**：标注员略偏爱长回答 → 裁判学到"长 = 好" → 长而空的回答拿高分（玩具里 9.1 > 简洁准确的 6.5）。

### 2. RLHF 与 KL 绳子（rlhf.py）
- 流程：裁判冻结 → 模型生成 → 裁判打分 → 按分数改模型。
- 只追分数会**钻裁判的空子**：β = 0 时 99.8% 概率选长废话，裁判分涨，真实质量跌。
- **KL 绳子**：分数里减去 β · ln(p 现在 / p 训练前 SFT 模型)，离 SFT 模型越远扣得越多。β = 3 时长废话 9.1 − 3·ln6（5.38）= 3.72 < 6.5，真实质量最好（6.46）。β 太大就什么都学不到。
- 最优解有闭式：**p ∝ p_SFT · e^(r/β)** → 这就是 DPO 的出发点。

### 3. PPO：真实 RLHF 怎么改模型（ppo.py、ppo_gpt2.py）
- **4 个模型**：
  | 名字 | 别名 | 状态 | 作用 |
  |---|---|---|---|
  | 策略模型 policy | actor | 训练 | 生成回答，被改的那个（SFT 模型复制一份） |
  | 参考模型 reference | — | 冻结 | 另一份 SFT 模型，算 KL 绳子 |
  | 奖励模型 RM | — | 冻结 | 给整句一个分（只在最后一个 token） |
  | 价值模型 value | critic | 训练 | 给**每个 token** 一个 V：从这里往后预计还能拿多少分 |
- **每个 token 的奖励**：r_t = −β · ln(p_t / p_ref,t)，最后一个 token 再加 RM 分数。第一轮两个模型一样，绳子是 0。
- **优势（功劳）用 GAE**：δ_t = r_t + V_{t+1} − V_t（这一步比预期好多少）；A_t = δ_t + γλ · A_{t+1}（λ = 0.95，把后面的惊喜往前分一点）。价值模型的训练目标 G_t = A_t + V_t（MSE）。
- **clip**：生成一次很慢，同一批数据要反复用 K 轮（4 轮）。ratio = e^(logp_new − logp_old)，logp_old 是生成时记下的每个 token 的 log 概率。ratio 超出 [0.8, 1.2] 且还在往同方向推时，**这个 token 的梯度归零**（开关），不是限制权重。
- **绳子 vs clip**：绳子管"离 SFT 模型多远"（整个训练），clip 管"这一批数据别改过头"（这批的 K 轮内）。
- 玩具 token 表（您好|亲|点申请|退款）：V 3.7/3.5/1.8/4.9，δ −0.2/−1.79/+3.1/+1.1，"亲"被罚（偏离 SFT 模型 + 后面变差），"点申请"功劳最大。

### 4. DPO：不要裁判、不要 RL（dpo.py）
- 从闭式解倒推：**隐含奖励 r = β · (logπ(回答) − logπ_ref(回答))**，即"这个回答的概率比训练前 SFT 模型涨了多少"。
- loss = **−ln σ(r_chosen − r_rejected)**，和奖励模型的 loss 一模一样，只是分数换成了概率比。
- 推力 = σ(−差距)：差距 0 时 0.5，差距越大推得越小。更新方向 = β · 推力 · [↑ logπ(chosen) − ↓ logπ(rejected)]，两个回答共同的部分抵消。
- β 是绳子：β = 0.1 时要 log 概率比相差约 46 才算"差距够大"，所以模型不会离 SFT 模型太远。
- **整句级**：只看整句 log 概率的和，不知道哪个 token 关键（第一个 token "Sorry" 反而被压低了）。
- **DPO 的两个常见毛病**（这周亲手撞到）：
  1. **chosen 跟着 rejected 一起往下掉**：loss 只看差距，压低 rejected 最省事。
  2. **腾出来的概率流到第三种回答**：两个都降了，概率去了没见过的胡编回答。loss 0.002 很漂亮，行为却没变。
- 修法：再加一项 **SFT loss（α · NLL）在 chosen 上**（Llama 3 用 α = 0.2，chosen 是模型自己生成的；我们的 chosen 是全新的人写句子，所以用 1.0）+ **"正确回答 ≻ 拒答"** 对，防止误拒。
- 什么时候算训练完：固定 1～3 个 epoch，看留出集上的**生成指标**（拒答率、正确率、误拒率），没有"差距达到多少"的目标。
- 显存：策略 112 GB + 参考 14 GB = **126 GB**（7B），是 PPO 252 GB 的一半。

### 5. GRPO：一题采一组，组内比高低（grpo.py）
- 每个问题采 G 个回答（G = 8；DeepSeekMath 用 64），**规则**打分。
- **组内优势 A_i = (r_i − 组平均) / 组标准差**，同一个回答的每个 token 共用这个 A。"同组其他回答的平均分"代替了价值模型的 V，所以不要 critic。
- loss = −A · logπ(token) + β · KL（k3 估计式 e^(ref−π) − (ref−π) − 1，β = 0.04）。KL 直接放进 loss，不进奖励。
- **全对或全错的组 A 全是 0，白采**：题目要难度适中（DAPO 的动态采样会把这种组丢掉重采）。
- **奖励量什么，模型就学什么**：只看答没答对时，"停住"和"啰嗦"拿一样的分，模型学不会停；加格式分后才学会。
- 显存：去掉价值模型和奖励模型 → 和 DPO 一样约 **126 GB**（7B）；但要在线生成，时间花在采样上。

### 6. DeepSeek-R1（概念课，见 r1-pipeline.html）
- **R1-Zero（实验）**：V3-Base 直接 GRPO，不做 SFT；奖励全是规则（准确率 + `<think>` 格式），不用奖励模型（怕被钻空子、太贵）。AIME 2024 pass@1 15.6% → 71.0%（多数投票 86.7%）；回答自己越写越长、出现自我检查（aha moment）；但可读性差、中英混写。
- **R1 四个阶段**：
  1. 冷启动 SFT：几千条规整的长思维链（可读性 + 让 RL 一开始就有对有错）
  2. 推理 RL（GRPO）：准确率 + 语言一致性奖励（治中英混写，推理分略降）
  3. 拒绝采样 + 再 SFT：约 60 万推理 + 20 万通用 = 80 万条，回到 V3-Base SFT 2 个 epoch
  4. 全场景 RL：推理题规则奖励，通用题奖励模型（有用、无害）
- **蒸馏**：用那 80 万条直接 SFT Qwen2.5 / Llama 小模型（R1-Distill）。只做 SFT。32B 上对比：自己 RL 47.0%，蒸馏 72.6%。
- **回答越写越长的原因**：奖励只看对错 → 想得久（验算、重试）更容易对 → 组内高于平均、A > 0 被推高 → 长度是副作用。
- 没成功的尝试：过程奖励模型 PRM（"一步"难界定、难标、易被钻空子）、MCTS（语言搜索空间太大）。

### 方法对照
| | SFT | 奖励模型 + PPO | DPO | GRPO |
|---|---|---|---|---|
| 数据 | 示范回答 | 偏好排序 + 在线生成 | 偏好对（离线） | 题目 + 可检查的答案（在线生成） |
| 训练的模型 | 1 | 策略 + 价值（+ 先训 RM） | 1 | 1 |
| 冻结的模型 | 0 | 参考 + RM | 参考 | 参考（+ 规则或 RM） |
| 7B 显存 | 112 GB | 252 GB | 126 GB | 126 GB |
| 能自己探索新解法 | 否 | 是 | 否 | 是 |
| 适合 | 学格式、话术 | 通用对齐（贵） | 有偏好数据、要省 | 有对错可判（数学、代码、SQL） |

## 关键代码
```python
# SFT:问题部分不算 loss
labels = [-100] * len(prompt_ids) + answer_ids
# 奖励模型 / DPO 共用的 loss 形状
loss = -F.logsigmoid(r_chosen - r_rejected).mean()
# DPO:分数 = 概率比 SFT 模型涨了多少
r_c = BETA * (pol_c - ref_c); r_r = BETA * (pol_r - ref_r)
loss = -F.logsigmoid(r_c - r_r).mean() + NLL_ALPHA * (-(pol_c / n_c).mean())   # 修复版加 SFT 项
# PPO:clip
ratio = torch.exp(logp_new - logp_old)
loss = -torch.min(ratio * A, ratio.clamp(0.8, 1.2) * A).mean()
# GRPO:组内优势 + KL 放进 loss
A = (r - r.mean()) / (r.std() + 1e-4)
kl = torch.exp(lp_ref - lp) - (lp_ref - lp) - 1
per_tok = -A.unsqueeze(1) * lp + BETA * kl
```

## 实验结果
- **sft.py**（GPT-2，ShopX 客服 36 条）：一个样本 34 个 token 只算 25 个（73.5%）。5 轮：留出集 loss 4.57 → 0.54，5/6 开头答对但停不下来，"法国首都"答成运费。10 轮：loss → 0.24，4/6（取消、改地址答成退款）。
- **reward.py**：真实权重里长度占 1.0 时，长废话 9.1 分胜过简洁准确的 6.5。
- **rlhf.py**：β = 0 → 99.8% 长废话；β = 3 真实质量最好 6.46；β = 10 几乎不动。
- **ppo.py**：同一批数据用 10 轮，不 clip 8 次里崩 2 次，clip 8/8 稳定在 6.46。
- **dpo.py 第一版（纯 DPO）**：loss 0.002，chosen +28.89，rejected −37.43，拒答 0/6，网店题 4/6 → 3/6。原因：法国题第一个 token "Sorry" 概率 2.05e-6 → 3.1e-7（排名 1953 → 4204），首 token 从 "Standard" 58% 变成 "The" 24%（胡编）；12 道网店题的 chosen 全部下降。
- **dpo.py 修复版（+ SFT 项 α = 1.0 + "正确 ≻ 拒答"对）**：loss 0.010，拒答 5/6，网店 4/6；"Sorry" 首 token 96.7%；12 道网店题 chosen 全部上升。
  - α = 0.2、没有"正确 ≻ 拒答"对：拒答 6/6，但 3 道网店题也被拒（误拒）。
  - 只用无关题（ONLY_OFFTOPIC）：网店 4/6 → 1/6。
- **grpo.py**：只看准确率：答对 9 → 10，正好停住 5 → 5；加格式分：9 → 10，5 → 8。每轮 4 组里 2～4 组"分全一样"。

## 售前账本
- 7B 训练显存（fp16 + Adam，训练的模型 16 字节/参数，冻结的 2 字节/参数）：SFT 112 GB → 2 × 80 GB；DPO / GRPO 126 GB；PPO 252 GB（多一个要训练的价值模型）。
- 选型一句话：**学格式用 SFT；有偏好对用 DPO；答案能自动判对错用 GRPO；要小模型会推理先蒸馏。**
- "本地部署了 DeepSeek-R1" 跑在一张卡上的 7B/14B/32B 都是 R1-Distill（Qwen/Llama 学了 R1 的写法），不是 671B 的 R1。
- 金融等敏感数据：用 API 生成蒸馏数据会出域 → 本地部署老师模型或脱敏。

## 我的提问与解答
完整记录见 [`week9/qa-log.md`](../week9/qa-log.md)（约 70 个问题）。精选：
- **PPO 是训练裁判的吗？** 不是。裁判先单独训好、冻结；PPO 训练的是策略模型（和价值模型）。
- **SFT 在 PPO 里扮演什么？** 两个角色：起点（策略模型从它复制）和绳子的另一头（参考模型是它的冻结副本）。
- **clip 的 20% 改的是权重吗？** 不是。限制的是每个 token 的概率比 new/old，超了就把这个 token 的梯度关掉；权重照常通过反向传播一起动。
- **裁判只给整句一个分，每个 token 的分怎么来？** 前面每个 token 只有 KL 绳子的分，最后一个 token 加 RM 分；再用价值模型 + GAE 把功劳分回每个 token。
- **价值模型第一个 V 怎么来？** 随机初始化（或从 RM 初始化），跟着训练用 G = A + V 当目标慢慢学准。
- **为什么算完 loss 要平均？** 回答长短不一，求和会让长回答的梯度更大、学习率要跟着变。
- **DPO 为什么只看整句？我的问题在第一个 token 没被推吗？** DPO 只看整句 log 概率之和，整句差距拉开了，但 "Sorry" 这个关键首 token 反而被压低。
- **chosen 跟着掉是什么毛病？** loss 只看差距，压 rejected 最省事；chosen 也降，腾出的概率给了胡编。
- **加了 SFT 项为什么又误拒？** 拒答句子被大力推高，网店题的"拒答"概率也跟着涨；加"正确 ≻ 拒答"对把它压回去。
- **R1-Distill 的 distill 是什么？** 大模型写答案，小模型 SFT 照着学；和 sft.py 一样，只是数据是 R1 写的。

## 易错点
- **训练谁、冻结谁**：PPO 训练策略 + 价值，冻结参考 + RM。裁判不是 PPO 训练的。
- **价值模型给每个 token 一个 V**，不是给每个回答一个分。
- **clip 管的是概率比，不是权重**；"跳过"只在这一批的 K 轮内。
- "SFT 概率"要说成"**训练前 SFT 模型给的概率**"。
- **DPO 的 loss 低 ≠ 行为对**：一定看生成结果（拒答率、正确率、误拒率）。
- **显存别忘梯度和 Adam**：训练的模型 16 字节/参数（7B DPO 是 126 GB，不是 28 GB）。
- 答题只写结论、不写机制（L4、L4b 都丢在这）：写"为什么会这样"那一步，比如"越写越长 = 想得久更容易对 → A > 0 被推高"，而不是"内容更多"。
- 周测（约 2.7/5）：5 题结论基本都对，但"两种修法 + 代价""每个选择一句理由"这些要求都没写完。
  - 第 1 题只给了一种修法（加大 KL β），漏了代价（β 大了学得少）和第二种（用长度均衡的数据重训 RM / 长度惩罚 / 人工抽查早停）。
  - 第 2 题：GRPO 解决的是**基线**（组平均代替 V），不是逐 token 功劳；GRPO 里同一回答的每个 token 也共用一个 A。
  - 第 3 题：SFT 项是**训练时的修法**，不是验收指标；验收要看生成结果：留出集拒答率、网店题正确率、误拒率。
  - 第 4 题：全对多 = 题太简单 → 换难题 / 丢掉这些组（动态采样），不是往组里塞错误答案；全错多 = 题太难或格式没对上 → 先冷启动 SFT、换简单题、检查奖励函数、加大 G 或给部分分。

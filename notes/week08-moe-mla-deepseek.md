# 第 8 周：MoE、MLA 与 DeepSeek-V3

日期：2026-11-12 晚（21:37–23:20 PT）· 代码：`week8/` · 周测：约 3.0/5

## 一句话总结
DeepSeek-V3 的骨架还是 Transformer + LLaMA 那一套（RMSNorm、SwiGLU、RoPE），只改了两个最贵的地方：**FFN 换成 MoE**（256 个小专家选 8 个 + 1 个共享专家，每个 token 只算 37B / 671B），**注意力换成 MLA**（KV cache 只存一个 512 维的压缩向量 c + 64 维位置小 k，每 token 69 KB，比 LLaMA-3 8B 还小）。结果：**大模型的知识，中等模型的计算成本**；但 **MoE 省算力不省显存**，671B 都得放进显存。

## 核心概念

### 1. MoE：一个 token 只挑几个专家（moe.py）
- 普通 FFN 是一个大盒子，每个 token 乘全部参数。MoE 把它换成 N 个小 FFN（专家）+ 一个**路由器**。
- **路由器就是一个 wx**（d × N 的矩阵）→ N 个分数 → softmax → 留 top-k → 在被选中的里重新归一化 → 加权相加。其余专家这次一个乘法都不做。
- MoE 是**模型结构本身**：训练和推理都这样跑。推理时所有专家都要放显存（不知道下个 token 挑谁），但每个 token 只算 k 个。
- Mixtral 8x7B：把 Mistral 7B 每层的 FFN（4096→14336→4096）复制 8 份，选 2。一个专家 3 × 4096 × 14336 = 176M；32 层 × 8 = 45.1B；加注意力 + 词表 1.6B = **46.7B 总参数**；激活 176M × 2 × 32 + 1.6B = **12.9B**。不是 56B，因为注意力没复制。
- **省算力不省显存**："按 47B 准备显存，按 13B 的速度跑"。decode 单用户只需搬被选中的专家，所以也快。

### 2. 负载均衡（balance.py）
- **强者越强**：被多选的专家训练得多 → 更容易被选 → 其他专家饿死。坏处：①饿死的专家白占显存；②多卡专家并行时每步等**最忙的卡**（最忙 2.8 倍 → 整步慢 2.8 倍）。
- 老办法：**辅助损失**（分不均就扣分），会和主目标抢梯度。
- **DeepSeek-V3：无辅助损失的偏置 b**。挑专家用"分数 + b"，每步后忙的 b 减 γ、闲的 b 加 γ。b **只管挑谁，不进加权权重**——分流和"听谁多少"分开，输出不受影响。γ 太大（0.5）会调过头来回晃；γ = 0 就退回强者越强。训练完 b 固定。
- **DeepSeekMoE**：①**细粒度专家**：切小、多选，C(8,2)=28 种组合 → C(256,8)≈4×10¹⁴ 种；②**共享专家**：每个 token 必走，存通用知识。
- 推理时仍可能不均（一批全是代码请求），部署用**冗余专家**（热门专家多复制几份）。

### 3. MLA：把 KV cache 压扁（mla.py）
- 把第 3 周的 W_k、W_v 拆成两步：c = x · **W_down**（7168 → 512，所有头共用，**只存 c**）；k = c · **W_uk**，v = c · **W_uv**（512 → 128，每个头各一对，u = up 展开）。
- 只存 c 就够：W_uk、W_uv 是**权重**（全模型一份，算在 671B 里），k 随时能从 c 算出来；KV cache 是**每个 token 的值**，随上下文增长。
- 和 GQA 比：GQA 是几个头**共用** k、v（头少了，效果掉）；MLA 每个头还能展开出自己的 k、v（代价：压缩丢一点信息 + 多一些计算 + 更复杂）。
- 朴素用法每步要把所有 c 展开 → 算得多。**吸收技巧**：q·(c W_uk) = (q W_ukᵀ)·c，把 W_uk 并到 q 上，c 不用展开；v 那边先在 c 上加权平均，最后展开一次。
- **RoPE 的麻烦**：k 要按位置旋转，每个 token 角度不同，夹在中间就没法提前合并。解法：另存一个 **64 维小 k 专门带位置**（所有头共用），c 部分不旋转继续吸收。每 token 每层 **512 + 64 = 576** 个数。
- 训练整句一起算，不用 KV cache；V3 从设计起就没有 W_k、W_v。

### 4. DeepSeek-V3 全景（v3.py）
| | GPT-2（第 3 周） | LLaMA（第 6 周） | DeepSeek-V3 |
|---|---|---|---|
| 归一化 | LayerNorm | RMSNorm | RMSNorm |
| 位置 | 学出来的 | RoPE | RoPE（拆出 64 维小 k） |
| 注意力 | MHA | GQA | **MLA** |
| FFN | 普通 | SwiGLU | SwiGLU + **MoE**（256 选 8 + 1 共享） |
| 负载均衡 | — | — | **偏置 b** |

- 配置：d = 7168，61 层（前 3 层普通 FFN，后 58 层 MoE），128 头，专家中间层 2048，词表 129280。
- 一层注意力 187M；一个专家 3 × 7168 × 2048 = 44.0M；一层 MoE 257 个专家 = 11.32B。
- 总：注意力 11.4B + 普通 FFN 1.2B + MoE 656.6B（**97.8%**）+ 词表 1.85B = **671.0B**。
- 激活：11.4 + 1.2 + 9 × 44.0M × 58（23.0B）+ 1.85 = **37.4B**（5.6%）；注意力占激活的约 30%。
- 训练：6 × 37B × 14.8T ≈ 3.3×10²⁴，稠密 671B 要贵 18 倍。约 278.8 万 H800 小时 ≈ $5.6M，只是最后一次训练的租卡价（不含研究实验、数据、人员、买集群）。

## 关键代码

```python
scores = x @ W_router; probs = softmax(scores)            # 路由器 = wx
top = np.argsort(probs)[::-1][:TOP_K]
gate = probs[top] / probs[top].sum()                       # 重新归一化
out = sum(g * run_expert(i, x) for g, i in zip(gate, top))
bias -= GAMMA * np.sign(load - ideal)                      # V3 偏置：忙减闲加，只用于挑选
C_cache = X @ W_down                                       # MLA 只存 c
q_c = W_uk[h] @ q[h]; w = softmax(C_cache @ q_c / np.sqrt(D_HEAD))   # 吸收技巧
out_h = (w @ C_cache) @ W_uv[h]
```

## 实验结果
- moe.py：玩具 4 专家 top-2 激活 53%；随机路由下 1000 token 负载均匀（489~515）。
- balance.py：不管 → 最忙 178 次、最闲 0 次（理想 64，2.8 倍）；偏置 γ=0.05 → 1.2 倍；γ=0.5 → 1.3 倍（调过头）。
- mla.py：朴素展开 vs 吸收技巧最大差 9e-16。每 token KV：LLaMA-3 8B 128 KB；V3 若 MHA 3904 KB（128K 上下文 488 GB/请求）、若 GQA 244 KB、实际 MLA **69 KB**（8.6 GB/请求），小 57 倍。
- v3.py：亲手算出 671.03B / 37.44B。

## 售前账本
- V3 FP8 权重 671 GB：8 × H100（640 GB）放不下 → **8 × H200**（1128 GB，剩 457 GB ≈ 650 万 token ≈ 50 个 128K 请求）；或两台 8 × H100（跨机通信慢）；或 int4 ≈ 350 GB 放进 8 × H100（效果掉一点）。
- 30B-A3B 类 MoE 上 4090：fp16 60 GB 放不下，int4 15 GB 放得下；单用户 decode ≈ 1000 ÷ 1.5 ≈ 670 token/s，同 int4 稠密 30B ≈ 67 token/s。
- 一句话："跑起来像 37B 一样快，但要按 671B 准备显存；MLA 让长上下文的 KV cache 几乎不是问题。"

- **RoPE 是乘 cos？** 是两两旋转（cos、sin 都用）；cos 出现在 q·k 的结果里 = cos(相差角度)，"cos 表示距离"在点积层面对，但要 64 组不同转速。

## 易错点
- **数字一定算到最后一个数**（复习、L3、周测第 2/4/5 题都丢在这）。用 python3 当计算器。
- 128K = **131072**，不是 128。
- int4 = **0.5 字节/参数**（3B → 1.5 GB，不是 3 GB）。
- FFN 不是 d×d 方阵，中间层会放宽（4096 → 14336）；矩阵参数 = 行 × 列。
- MoE **省算力不省显存**；Mixtral 不是 8 × 7 = 56B，注意力没复制。
- 偏置：忙的**减**，闲的**加**；只用于挑专家，不进权重。
- 权重（一份、固定）vs KV cache（每 token、增长）——第 6 周以来的老坑。
- 售前回答没有数字就没有说服力（周测第 5 题）。

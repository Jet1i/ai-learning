# 第 5 周：Embedding、RAG、检索 MCP Server、评测 → 项目 1

日期：2026-11-09 · 代码：`week5/` · 项目：`week5/project1/` · 周测：约 3.6/5

## 一句话总结
RAG = **先找资料，再让大模型照着资料回答**：离线把文档切块、向量化；在线把问题向量化，取最像的 k 块拼进 prompt，再由大模型生成。检索做成 MCP Server，所有 Agent 都能用。好不好不能凭感觉，要靠测试集和数字来判断。

## 核心概念

### 1. Embedding 与相似度（embed1.py）
- Embedding 模型把一句话变成一个定长向量（bge-small-zh-v1.5：512 维，4 层，8 头，约 95MB，Mac CPU 就能跑）。意思越近，方向越近。
- **余弦相似度** = a·b / (|a||b|)，范围 -1～1。先 normalize（模长变成 1），点积就**等于**余弦，`D @ q` 一行就能给所有文档打分。不 normalize，模长会混进分数，长的向量占便宜。
- 字袋法只看字面（"快递"和"物流"对不上，还会被"了"带偏）；bge 看意思。
- 点积为什么能代表"相关"：是**训练**让它有了这个意思。bge 用对比学习（配对句子的向量要靠近，用 softmax + 交叉熵），attention 的 Wq、Wk 由 loss 来调整。
- **[CLS]**：分词器加在句首的特殊 token。Encoder 是双向的，每一层都用 attention 对全句做加权平均，所以它就成了句向量。其他取法：平均池化；Decoder 取最后一个 token（因为有因果 mask）。

### 2. 第一个 RAG（rag1.py）
- 离线：切块 → 向量化 → 存储（向量 + 原文 + 出处）。在线：问题向量化 → top-k → 拼进 prompt → **生成**。
- 切块：按小标题 / 段落切，相邻块重叠；每块带上"文档标题 - 小标题"。块太大，话题混在一起，向量被"平均"了；块太小，句子被切断，答案散落多块，top-k 装不下。
- bge 的分数不会到 0，每个问题总有第 1 名 → 需要**门槛**，加上 prompt 里的"资料里没有就说不知道"。
- 向量数据库 ≠ 结构化：它是一个"语义索引"，原文和元数据要一起存；核心能力是近似最近邻搜索（HNSW）。客户已经在用 PostgreSQL 的话，可以用 pgvector 起步。

### 3. 检索 MCP Server + Agentic RAG（kb_server.py / kb_agent.py）
- 把 `search()` 包装成 MCP 工具；kb_agent = 第 4 周的 mcp_agent，只换了 Server 和 system prompt。
- 固定 RAG：每问必查一次。Agentic RAG：由模型决定查不查、查几次、用什么 query（会拆问题、改写 query；但更慢、更贵，还可能该查的时候不查）。
- stdio 模式下 stdout 是协议通道，日志要写到 stderr。stdio 只能在本机用；Streamable HTTP 可以远程、多客户端，需要鉴权。
- 模型没见过你写的工具，但训练过"读工具说明书"这项通用能力（上下文学习）。所以 description 要写清楚什么时候用、query 该怎么写。

### 4. 评测（eval.py）
- 检索：Hit@k；门槛扫描（门槛高 → 拒答更准，但会误挡能答的题）。0.7 只放行 2/12，0.55 是 10/12 + 4/4。**门槛是业务取舍**（客服宁严勿松）。
- 回答：关键词检查（便宜、死板）+ LLM 裁判（灵活、要花钱）；两者不一致的人工看。
- 测试集太小会过拟合；出题人知道答案，容易"放水"。

### 5. 项目 1：学习笔记问答 Agent（project1/）
- Markdown 感知切块、bge + BM25 **混合检索**（RRF 融合）、向量缓存、`read_section` 小块检索大块返回、`--http` 远程模式、三种检索方式对比评测。
- 三道防线：相似度门槛（只防跑题）→ LLM 判断资料够不够（prompt）→ rerank 模型。

## 实验结果
- L1：字袋法在"快递到哪了"上排错，bge 对；知识库答不了的问题，最高分也不会接近 0。
- L2：40 字一块、不重叠 → 15 块变成 35 块，复合问题答坏了。
- L3：复合问题被拆成多次检索（query 像关键词）；"你好""1+1"不检索。
- L4（云帆云，16 题）：门槛 0.70 只放行 2/12，0.55 → 10/12 能答 + 4/4 拒答；"AccessKey 传到 GitHub"没排第 1（英文弱 + 需要常识）；关键词检查误判 1 道。
- 项目 1（我的笔记，12 + 2 题）：vector Hit@1 9/12、Hit@4 11/12；bm25 8/12、12/12；**hybrid 11/12、12/12**；能答的题误挡 0/12；vLLM、LoRA 没挡住；Agent 对 LoRA 标注了"（笔记外补充）"。

## 我的提问与解答
完整记录见 `week5/qa-log.md`。
- **为什么点积大就代表相关？** 点积 = 每个维度上"意见一致"的程度；是训练让方向承载了意思（attention 的 Wq/Wk、bge 的对比学习）。
- **bge 用问答对训练吗？大模型也是吗？** 都用问答对，但 bge 学的是"找"（向量靠近），大模型 SFT 学的是"写"（逐 token 生成）。RAG 正好是这个分工。
- **向量数据库是把数据变成结构化了吗？** 不是。它是语义索引：维度没有含义，不能写 WHERE，而且是有损的；元数据才是结构化的。
- **"长文档占便宜"跟向量长度有关吗？** 区分维度、模长和文本长度。字袋法里文本越长模长越大；bge 统一 normalize 来解决。
- **[CLS] 是什么？每一层怎么总结？** 句首的特殊 token；每层用 attention 对全句做加权平均（再加残差、过 FFN），一层层从字级汇总到句级。（纠正：bge-small-zh 是 4 层，不是 12 层。用参数公式验算：12·4·512² + 21128·512 ≈ 2340 万 ≈ 94MB。）
- **三种取句向量的方法？** 看谁"看全了整句"（见 pooling-demo）。
- **stdio 和 HTTP？** stdio 是本地子进程；HTTP 可以远程、多客户端，要做鉴权。
- **模型怎么知道去调工具？工具是我写的，它训练过吗？** 工具说明会被写进 prompt；训练练的是"读说明书"这项通用能力，调用本身也是在预测下一个 token。
- **Agentic RAG 一定把 query 写成关键词吗？** 不一定，那是它的习惯；bge 更适合完整问句，用 description 来控制。其他做法：multi-query、HyDE、混合检索。

## 易错点
- RAG 的最后一步是**生成**：检索拿回来的是资料，不是答案。（周测第 1 题）
- cos 的范围是 -1～1，不是 0～1。不 normalize，点积 ≠ 余弦。
- 门槛别凭几道题来定，要用测试集扫；它只挡得住跑题的问题，挡不住同领域的。
- 回答选型问题时用"数据 + 替代方案 + 业务取舍"来组织，不要只说"会拦住"。（周测第 4 题）
- ✅ 第 4 周的老问题已经解决：两个停止条件（没有 tool_calls / 最大步数）。

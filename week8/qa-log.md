# 第 8 周提问记录(MoE、MLA、DeepSeek-V3)

## L1 MoE

**Q:MoE 是换成了 8 个同样大小的 FFN?这是训练大模型时说的吧,不是使用时?**
A:训练和使用都是。MoE 是模型结构本身:设计时就决定每层 FFN = 8 个专家 + 路由器,推理时每个 token 在每层现场打分挑 2 个。部署时 8 个专家都要放显存(不知道下个 token 挑谁),但每 token 只算 2 个。"同样大小"指 Mixtral(把 Mistral 7B 的 FFN 4096→14336→4096 复制 8 份);DeepSeek 把专家切小(V3 中间层 2048,256 选 8)。

## L2 负载均衡

**Q:偏置 b 是训练时加的吧?防止练出来有些专家没被选上。**
A:对,b 在训练时每步调整。训练完 b 固定,成为路由器的一部分,推理时挑专家仍用"分数 + b"但不再更新。推理时一批请求偏某类(如全是代码)仍可能不均,部署时 DeepSeek 用"冗余专家"把热门专家多复制几份到不同卡上分流。

## L3 MLA

**Q:W_uk、W_uv 是什么?**
A:把第 3 周的 W_k、W_v 拆成两步。c = x·W_down(7168→512,所有头共用,只存 c);k = c·W_uk,v = c·W_uv(512→128,每个头各一对)。u = up(展开)。都是训练学出来的普通权重。比喻:W_down 打包,W_uk/W_uv 解压。吸收技巧 = 不解压,把 W_uk 先乘到 q 上,直接和 c 比。

**Q:MLA 为啥不用存 W_uk、W_uv,只存 c?**
A:W_uk/W_uv 也存了,但它们是权重:全模型一份、所有 token 共用、算在 671B 里、开机加载不变。KV cache 是每个 token 算出来的值,随 token 数增长。k = c·W_uk 随时可算,所以只需存每 token 的 c。V3 一层:W_uk+W_uv 固定 1680 万数;MHA 10 人×128K 的 k+v ≈ 430 亿数;MLA 的 c ≈ 7.5 亿数。比喻:菜谱(W)一本,每桌只记点单(c)。(又是"参数 vs 算出来的值"这个老坑)

**Q:那训练时参数就变了?不存原来的 W_k、W_v,而是这几个?因为 KV cache 是 c。**
A:对。V3 从设计起就没有 W_k、W_v,参数表里是 W_down、W_uk、W_uv,直接训练这三个。补充:训练整句一起算,不用 KV cache;KV cache 只在推理逐字生成时用。训练决定"有哪些矩阵",推理因为矩阵这样设计才能只存 c。(也有研究把训好的普通模型改造成 MLA,需再训练。)

**Q:RoPE 是夹在 k 向量上的吧?乘了 cos?**
A:q 和 k 都转,v 不转;两两分组旋转,cos 和 sin 都用(x₁'=x₁cosθ−x₂sinθ, x₂'=x₁sinθ+x₂cosθ),θ=位置×频率。例:(1,0) 每位置 30°,第 2 位 → (0.5, 0.87)。卡住吸收的原因:旋转夹在 c·W_uk 和 q 之间,每个 token 角度不同,无法提前并成一个固定矩阵。所以 DeepSeek 拆出 64 维小 k 单独旋转,c 部分不转、继续吸收。

**Q:那两行旋转公式啥意思?我理解是乘 cos 表示,cos 表示距离更远?**
A:公式只是"把点转 θ 度、长度不变"的写法:(1,0)→(cosθ,sinθ),(0,1)→(−sinθ,cosθ),任意点按份数组合。cos 出现在点积结果里:q=(1,0) 不转,k=(1,0) 在位置 m 每位 30°:q·k = 1, 0.87, 0.5, 0(m=0..3)= cos(相差角度)。所以"cos 表示距离"在点积层面对。坑:cos 有周期,真实 RoPE 用 64 组不同转速,合起来才"越远越低"。

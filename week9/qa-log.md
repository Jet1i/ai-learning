# 第 9 周提问记录

## SFT 和 LoRA 是什么关系?SFT 必须一问一答吗?(L1)
- SFT 管"学什么"(模仿标准回答,交叉熵);LoRA 管"改哪些参数"(冻住 W,只训小矩阵 A、B:Wx + B(Ax);4096×4096、r=8 → 65,536 个,约 0.4%)。可以组合:全参 SFT、LoRA SFT、LoRA DPO……
- SFT 不一定一问一答:多轮对话、工具调用轨迹都行。关键是 loss 只算 assistant 部分(user / tool 内容 mask 掉)。
- 没有问答结构的纯文本接着训 = 继续预训练,不是 SFT。

## L2 里"抽到简洁准确"什么意思?打分不需要和其他回答比较吗?(L2)
- 真实 LLM 生成任意文字;玩具里缩成 5 种回答,"抽到"= 这次生成的正好是那一种。
- 比较只在训练裁判时用(L1 两两偏好)。训练好后裁判是 r = w·x,单个回答直接出分(看 4 个特征 × w)。L2 的 6.5 / 9.1 就是 L1 练习 2 算出的分数。
- L2 唯一的"比较"是和 baseline(最近平均分)比,决定推高还是压低。
- 比喻:L1 用"哪道菜好吃"的投票培养评委;L2 厨师每做一道菜评委直接打分,厨师看比平时高还是低。

## KL 绳子到底干嘛?(L2)
- 裁判有盲点(偏爱长度),模型只追分会钻空子(学生发现老师只看字数就凑字数)。
- 规则:某回答现在的概率比 SFT 高越多,每次说它扣越多:β·ln(p/p_SFT)。β=3、废话(SFT 0.1、9.1 分):p=0.1 → 9.1;0.2 → 7.02;0.5 → 4.27。详细准确概率没变 → 6.5。废话涨到一定程度就不划算,停在平衡点(30% 废话)。
- 概率低于 SFT → log 为负 → 变加分,不会彻底忘掉。
- 真实 LLM 不拴绳会退化成骗裁判的怪话、丢掉语言能力;绳子让它只在 SFT 附近小步改进。

## 裁判为什么偏爱长回答?(L2)
- 玩具里是故意设的(TRUE_W 长度 1.0)。现实里叫 length bias:标注员时间紧没空核对事实;长回答看起来认真完整;短而正确显得单薄 → 稍微偏长 → 裁判学到 → RLHF 放大 → 模型越来越啰嗦。
- 同类偏见:附和用户(sycophancy)、自信语气、花哨格式。
- 应对:标注规范、长度惩罚、长度校正评测(AlpacaEval LC)。
- 售前:RLHF 上限取决于标注质量;评测看长度校正后的胜率。

## 标注员是真人吗?(L2)
- 最早是真人(InstructGPT 约 40 个外包标注员做二选一),贵、慢、有偏见;专业题要专家。
- RLAIF:强模型按原则清单判断 A/B(Anthropic Constitutional AI),快便宜但也有偏见。
- 规则校验:数学核答案、代码跑测试,对 1 错 0,没法骗 → L4 DeepSeek-R1 的关键。
- 实际混用。售前:能规则校验的场景(数学/代码/SQL)RL 最便宜最稳。

## "知道终点能不能直接训过去"是什么意思?(L2 → L3 预告)
- RLHF 绕路:偏好 → 裁判 → 生成几千次 → 打分 → RL → 停在 p ∝ p_SFT·e^(r/β)。
- DPO 抄近路:公式倒过来读 → 分数 = β·ln(p_现在 / p_SFT),LLM 自己就是裁判。
- 套 L1 的 loss:β=3,选中 0.3/0.25 → 0.55;没选 0.1/0.15 → −1.22;差 1.77,sigmoid = 0.854 → 往 100% 推。
- 不用裁判、不用采样、不用 RL,显存 2 个模型(PPO 要 4 个)。

## SFT 到底是什么?(L2)
- 三步:预训练(万亿 token 猜下一个字,只会续写,问"怎么退款?"可能接着写更多问题)→ SFT(几万条人写的示范问答,交叉熵模仿,只算助手部分;InstructGPT 约 1.3 万条)→ RLHF/DPO(用偏好调整好坏回答的概率)。
- SFT 模型在第 3 步还是绳子的桩子:复制一份冻住 = 参考模型(rlhf.py 的 REF_P)。
- 比喻:读遍图书馆 → 看客服示范学会接待 → 主管打分让回答更合心意。

## "loss 只算助手那部分"啥意思?(L2)
- 交叉熵:每个位置猜下一个字,loss = −ln p(正确字),取平均。
- 一条 SFT 数据:`用户: 怎么退款? 助手: 点申请退款`。只给助手的字算分:点 0.2 → 1.61、申 0.5 → 0.69、请 0.9 → 0.11,平均 0.80;用户部分(么 1.20、款 2.30)扔掉 = mask。
- 原因:用户问题是给定的题目,不想让模型学着提问,只学怎么回答。
- 和第 3 周比:只换了数据和算分位置,公式没变。

## "看概率比 SFT 涨了多少就能读出裁判的分数"怎么理解?(L2 → L3)
β=3 训练后:废话 0.10→0.301(×3.01),详细 0.25→0.316(×1.26),简洁 0.30→0.321(×1.07),敷衍 0.20→0.040(×0.20),胡编 0.15→0.022(×0.15)。
- 按倍数排序 = 裁判打分顺序。
- 裁判分 − 3·ln(倍数) 每行都 = 5.8(常数),分数整体加减不影响 → β·ln(倍数) 就是裁判分。
- 裁判的分数被写进了模型概率 → DPO:直接要求"人选的涨得比没选的多",不用裁判和 RL。

## "SFT 概率"是啥?SFT 不是微调吗?(L2)
- SFT(动作)= 微调过程;SFT 模型(结果)= 做完 SFT、还没 RLHF 的模型。"SFT 概率" = SFT 模型说出这个回答的概率 = "训练前的概率"。
- 模型每步 softmax 出下一个字的概率再抽 → 同一问题问 100 次答案不同:30 次简洁、25 详细、20 敷衍、15 胡编、10 废话 = REF_P。

## PPO 是啥?(L2)
- Proximal Policy Optimization 近端策略优化 = RLHF 第 3 步实际用的 RL 算法;rlhf.py 是简化版。Policy = LLM;Proximal = 每次只挪一小步。
- 多两样:① clip:每步概率最多变 ±20%(0.30 → 最多 0.36),防止运气好的高分把模型推跑偏;② 价值模型:给每个 token 估"照这样写下去能拿多少分",替代简单平均 baseline。
- clip 比上一步的自己(每步走多远);KL 比 SFT 模型(总共走多远)。
- 4 个模型 → DPO 去掉裁判 + 价值模型;GRPO 去掉价值模型。

## PPO 是用来训练裁判的吗?(L2.5)
- 不是。裁判在 L1 用 −log sigmoid(分差) 训好后冻住;PPO 训练的是 LLM(Policy)。
- PPO 时 4 个模型:LLM ✅ 训练(主角);价值模型 ✅ 一起训练(配角);裁判 ❌ 冻住;SFT 参照 ❌ 冻住。

## 一直提的 SFT 到底在说什么?(L2.5)
- 都是"做完 SFT 后的模型"。时间线:① 预训练 → ② SFT → SFT 模型(会问答)→ ③ 训练裁判(冻住)→ ④ PPO:SFT 模型复制两份,一份继续训练 = LLM(主角),一份冻住 = SFT 参照(绳子桩子)。
- SFT 模型既是 PPO 的起点,也是参照。"SFT 概率" = 冻住那份的概率 = 训练前的概率。DPO 同样两份,但不要裁判。

## PPO 里绳子在哪?(L2.5)
- PPO 不是"调参"(超参数),是改 LLM 权重。
- 一轮顺序:① 生成 → ② 算分(🪢 绳子:裁判分 − β·ln(p/p_SFT),和冻住的 SFT 比,管总距离)→ ③ 分功劳(价值模型)→ ④ 更新(clip:和上一版比,管每批推多猛)。
- 绳子 = 防钻空子;价值 = 分清功劳;clip = 防训练崩。绳子跟 SFT 比,clip 跟上一步的自己比。

## 有绳子了为啥还要 clip?(L2.5)
- 绳子管终点,clip 管每步速度。ppo.py 不限速那组本身拴着绳子(β=3),照样崩 2/8。
- 原因:绳子在算分时算;抽批时废话 p=0.1 = SFT → 扣 3·ln1 = 0;同一批反复更新 10 轮分数不重算,绳子一次都没拉 → 一批内 10% → 91%;下一批才扣分,但已几乎只说废话,拉不回。
- 比喻:绳子 = 最远离家 10 公里;clip = 每分钟最多 1 公里。限速让绳子每步都来得及重新拉。

## clip 的 20% 改的是大模型权重吗?那么多权重?(L2.5,02:34 Jet 自己找到卡点)
- 不是。20% 限的是输出概率。链条:几十亿权重 → wx+b … → logits → softmax → p(准确)。
- 改权重:反向传播算每个权重的梯度,全部一起挪一小步(w −= lr·梯度 / Adam)。
- clip 盯概率:p 0.40 → 0.44(×1.1)继续推;→ 0.49(×1.22 > 1.2)这条数据梯度设 0,不再影响任何权重。= 每条数据身上的开关。
- 真实 LLM 按 token 算 ratio,一个回答几百个 token 就几百个开关。

## 价值模型自己训练的意义?看概率变化有啥用?(L2.5,02:42)
- Jet 自己总结:PPO = 生成 → 和 SFT 比加绳子 → 分功劳 → 概率到 1.2 倍就不用这条,因为生成慢所以要反复用数据。✓
- 价值模型:真实 LLM 没法穷举算 V,只能从数据学:猜"客套后平均 3.0",实际 1.8 → 往 1.8 调,loss = (猜 − 实际)²。猜得准 → 功劳分得准。

## 价值模型学的"实际分数"从哪来?(L2.5,02:49)
- 来自裁判(减绳子)。裁判只在写完后给完整回答打分;价值模型在写到一半时猜最后能拿几分,拿裁判的最终分当答案学。
- 例:3 个客套开场的回答最终 6、−1、0.4 → 平均 1.8;价值模型猜 3.0 → 往 1.8 调。
- 比喻:裁判 = 期末考试;价值模型 = 老师学期中估分,靠真实期末成绩修正。

## 用功劳改权重,价值模型怎么一步步分的?(L2.5,03:04)
- 回答 `您好 | 亲 | 点申请 | 退款`,最终 5.45。价值模型在每个位置猜 V:3.7 → 3.5 → 1.8 → 4.9 → 真实 5.45。
- 每个 token 功劳 = 写后 V − 写前 V:−0.2、−1.7、+3.1、+0.55,加起来 1.75 = 5.45 − 3.7。

- 价值模型不是分类,是每个位置打预估分,相邻之差 = 功劳。(真实 PPO 再做 GAE 平滑。)

## 不要玩具,真实 LLM 的 PPO 怎么做?(03:10,Jet 被玩具搞蒙)
准备 4 个模型:π(SFT 复制,训练)、π_ref(SFT 复制,冻住)、RM(SFT + 标量头,冻住)、V(同 RM 结构但每个 token 输出一个数,训练)。
每轮:
1. 生成:512 条提示,π 逐 token 采样(≤512 token),记 logp_old。数据 = 512 × T 的表。
2. 四次前向(无梯度):π_ref → logp_ref;V → V_t;RM 在最后一个 token → R。
3. 每 token 奖励:r_t = −β(logp_old − logp_ref),β 0.01–0.1;最后一个 token 加 R。(绳子按 token 算,玩具里按整句是简化。)
4. GAE:δ_t = r_t + V_{t+1} − V_t;A_t = δ_t + 0.95δ_{t+1} + 0.95²δ_{t+2} + …;整批标准化;价值目标 G_t = A_t + V_t。
5. 同一批用 K=4 轮、分小批:logp_new,ρ_t = e^(logp_new − logp_old);策略 loss = −mean min(ρA, clip(ρ,0.8,1.2)A);价值 loss = mean (V_t − G_t)²;Adam 更新 π 和 V 全部权重(lr ~1e-6)。
6. 扔掉,回到 1。
监控:平均奖励、KL(π‖π_ref)、回答长度。

## 价值模型第一个 V 怎么确定?(03:26)
- V₀ = 价值模型读完提示词、在提示词最后一个位置的输出("一个字没写时预计能拿几分");和后面的 V 同一次前向算出(代码 value(...)[:, P-1:-1] 第一列)。
- 因题而异:"This movie was a masterpiece" V₀ 高,"...a waste of" V₀ 低;第一个 token 功劳 = V₁ − V₀,相对题目本身难易。

## PPO 也是按回答找 token 向量来算的吗?(03:37)
- 是。提示词 + 回答 → token 编号 → 查词向量(768 维)→ 12 层 Transformer(因果 mask)→ 每个位置隐藏向量 → LM head(wx+b)→ softmax → 取实际写的那个 token 的概率 → log = logp。一次前向得到所有位置,不用重新生成。
- 4 个模型读同一串 token,头不同:策略/参照 → 每 token 概率;价值 → 每位置一个 V;裁判 → 最后位置一个分。代码 token_logprobs()、token_values()。

## 裁判生成偏好吗?对照模型干啥?(03:41)
- 裁判不生成偏好,是学过人类偏好(A≻B)的模型,PPO 里只读完整回答给一个分。
- 对照模型 = 绳子另一头:每个 token 问训练中模型和对照模型的概率,比如 0.6 vs 0.2 → 扣 β·ln3 = 0.1×1.10 = 0.11。
- 必要性:裁判有盲点,只看裁判会越改越怪;对照 = 冻住的"原来的自己"。裁判告诉往哪走,对照拉着别走太远。

## 前面 token 裁判给 0,绳子是不是会变成加分?(03:55)

## PPO 展开来步骤这么多(04:32)
- 核心只有 3 个:裁判 + 绳子(方向 + 别跑远)、价值模型分功劳、clip 限速。
- 代价:4 个大模型同时在显存(7B fp16 权重 56 GB + 两个训练模型的梯度和优化器状态),超参多易崩。
- 简化路线:DPO 去掉裁判/价值/生成/clip,只剩 2 个模型;GRPO 去掉价值模型,用"比同组平均好多少"分功劳。

## 绳子的专业词是什么?(05:17)

### Q(19:51 PT):"同时记下每个生成 token 当时的 log 概率 logp_old" —— 这就是输出 token 的概率吗?

### Q(19:59 PT):critic 的 V_t、优势 A_t(GAE, λ=0.95)是怎么确定的?
- V_t:把「问题+回答」整条送进 critic 跑一次前向,每个位置的 hidden state 过一个 Linear(d→1) 得到一个数 = 「从这里往后预计能拿几分」。V_1 是生成第 1 个 token 之前(只看到问题)的预测。例:您好|亲|点申请|退款 → V = 3.7 / 3.5 / 1.8 / 4.9,结束后 V = 0。准不准靠训练:目标 G_t = A_t + V_t,loss = (V − G)²。
- 第 1 步 每个 token 的奖励:r = −β·ln(p/p_ref),最后一个 token 再加裁判分 R=6 → [0, −0.092, 0, 6.0]。
- 第 2 步 δ_t = r_t + V_{t+1} − V_t(这个 token 让 critic 的预期涨/跌了多少)→ [−0.2, −1.79, +3.1, +1.1]。
- 第 3 步 从最后往前:A_t = δ_t + 0.95·A_{t+1} → 退款 1.10,点申请 3.1+0.95×1.1=4.15,亲 −1.79+0.95×4.15=2.15,您好 −0.2+0.95×2.15=1.84。
- λ 的作用:λ=0 → A=δ,只信 critic 的一步判断(亲 = −1.79);λ=1 → A = 实际后面拿到的总分 − V_t,只看真实结果(亲 = +2.41);0.95 偏向真实结果、用一点 critic 降噪(亲 = +2.15)。λ 是超参数,不是学出来的,GAE 论文实验 0.92~0.98 好用,大家默认 0.95。
- 注意单条样本里「亲」仍是 +2.15:这条回答最后 6 分,比 critic 预期高,几乎所有 token 都沾光。要压低「亲」,靠很多条回答平均(还会做优势归一化:整批减均值除标准差)。
- critic 下一轮的学习目标 G = A + V = 5.54 / 5.65 / 5.95 / 6.0。

### Q(22:03 PT):V_t、A_t 的原理是什么?为什么要结合这两个来打分,再去改权重?
- 目标:改 actor 权重,让好 token 概率变高、坏 token 变低。只差一个「每个 token 推多少」的数,这个数就是 A_t。
- 跟 SFT 对比:SFT loss = −Σ 1 × logp(人写的 token),每个 token 权重都是 1,永远往上推;PPO loss ≈ −Σ A_t × logp(自己抽到的 token)(先不看 clip),权重是 A_t,可正可负。
- 为什么不直接用裁判分 R:问题 1 没有参照。同一问题,回答 X 得 6、Y 得 2,直接用 R 两个都往上推(+6、+2);减去预期 4 → +2、−2,好的推高、差的压低。V 就是这个「预期」(rlhf.py 里的 baseline 也是这个作用,critic 是按每个位置给的更细的 baseline)。问题 2 分不清功劳:一句话只有一个总分,每个 token 都拿 6 分没法区分。critic 每个位置给预期,δ = 说完这个 token 后预期变了多少(亲 3.5→1.8 = −1.79,点申请 1.8→4.9 = +3.1)。
- 类比:球赛直播的「胜率曲线」。critic = 胜率预测;δ = 这一脚让胜率涨/跌多少;R = 最终输赢;A = 这一脚的功劳。
- λ:critic 不一定准,GAE 把 critic 的逐步判断(稳但可能偏)和真实最终结果(真但吵)按 0.95 混合。
- 全流程:critic 算 V(预期)→ 加上真实奖励算 δ(意外)→ GAE 合成 A(功劳)→ loss = −A × clip(概率比)→ 反向传播改 actor 全部权重;critic 自己用 (V − G)² 训练。

### Q(22:08 PT):SFT 的 loss = −Σ 1 × logp(人写的 token) 是干嘛用的?
- loss = 一个数,衡量模型离「会说人写的答案」还差多远;训练 = 改权重让这个数变小(第 2 周 wx+b 的 (y−ŷ)² 同一套,只是公式换成交叉熵,即第 3 周 minigpt.py 的 loss)。
- 例:人写的答案 您好|请|点申请|退款。训练前模型在每个位置给「人写的那个 token」的概率 0.05/0.10/0.02/0.30 → ln = −3.00/−2.30/−3.91/−1.20 → 平均 loss 2.60;训练后 0.6/0.7/0.5/0.9 → −0.51/−0.36/−0.69/−0.11 → loss 0.42。
- 负号:p<1 所以 ln p 是负数,p 越大越接近 0。想让 p 变大 = 让 ln p 变大,但梯度下降只会「变小」,所以加负号。p=1 时 loss=0(最小)。
- Σ 只加助手部分的 token(用户部分 label=−100 不算);「1 ×」只是为了和 PPO 的「A_t ×」对照,意思是每个 token 一样重要、都往上推。
- 用法:loss.backward() 算出每个权重该往哪边动 → AdamW 走一步 → 下次模型更倾向说出人写的答案。sft.py 里 model(input_ids, labels=y).loss 就是它(HF 取平均)。

### Q(22:19 PT):critic 随机打一次分,然后 GAE 是 critic 的目标打分,对吗?(Jet 的理解,部分对)
- 「随机」只在最开始成立:ppo_gpt2.py 里 critic 的 Linear 头是新建的,一开始 V 基本是乱的;InstructGPT 用奖励模型初始化,一开始就大致靠谱。而且不是只打一次:每一轮、每条回答、每个 token 位置都打一个 V。
- GAE 算出的是 A(功劳),A 拿去改 actor。critic 的目标是 G = A + V(例:亲 V 3.5 + A 2.15 = 5.65),loss = (V_new − 5.65)²。λ=1 时 G 就是「从这里往后实际拿到的分」(5.91/5.91/6.0/6.0),所以 G ≈ 实际得分。
- 一句话:critic 每轮给每个位置一个预期 V → GAE 用 V + 真实奖励算出 A → A 改 actor;A + V = G 当 critic 的目标,让 V 下次更准。

### Q(2026-11-15 19:28 PT):sft.py 打印的 "new embeddings will be initialized from a multivariate normal ... mean_resizing" 是啥意思?
- 不是报错,是提示。resize_token_embeddings 把词向量表从 50257 行扩成 50260 行(每行 768 个数),多出的 3 行给 <|user|> <|assistant|> <|end|>,一共新增 3 × 768 = 2304 个参数。

- 为什么要这样:GPT-2 输入词向量和输出层共用同一张表(tie),新行也决定输出时这个 token 的分数 logit = h·e_new。如果新行很怪,训练一开始这 3 个 token 的概率可能离谱,打乱输出;像「平均词」就几乎不影响原来的概率分布(提示里的文章证明了这点)。
- 但它只是「像普通词」,并不知道自己的意思。<|end|> 要靠训练学会「该停了」,36 条数据每条只出现 1 次,5 轮没学会 → 回答停不下来,所以改成 10 轮。

### Q(2026-11-15 19:33 PT):裁判(奖励模型)打分是怎么做的来着?
- 结构:拿 SFT 模型,把最后输出 50257 个词分数的那层换成 Linear(768→1)。输入「问题+回答」→ Transformer → 取**最后一个 token** 的 hidden state h(768 个数)→ 分数 = w·h + b。取最后一个是因为因果注意力下只有它看过整段话。L1 reward.py 用的是 4 个手写特征,真实裁判的「特征」是 Transformer 学出来的 h。
- 训练数据:标注员给同一问题的 K 个回答排序(K=4 → C(4,2)=6 对;K=9 → 36 对)。
- loss = −ln σ(r_chosen − r_rejected)。例:好 2.0、差 0.5 → 差 1.5 → σ=0.818 → loss 0.20;打反了(差 −1.5)→ σ=0.182 → loss 1.70。b 相减消掉,只有差距有意义。
- 用的时候(PPO):冻结,一整条回答只给一个分(比如 6.0),放在最后一个 token 上。
- 和 DPO 的关系:DPO 用同一条 loss,只是分数换成 β·(logπ − logπ_ref),所以不用单独训裁判。

### Q(2026-11-15 19:34 PT):SFT 里 label 写 −100 怎么就不算问题部分的 loss 了?
- PyTorch 的交叉熵 F.cross_entropy 有个参数 ignore_index,默认就是 −100:label 等于 −100 的位置直接跳过,不算 −ln p,也不算进平均的分母。HF 模型内部就是调它。
- 为什么是 −100:只是约定的「暗号」。真实 token id 是 0~50259,不可能是负数,所以不会和真 token 撞。
- 例(三个位置,正确下一个 token 的概率 0.2 / 0.5 / 0.8,第一个是问题部分):不遮 → (1.609+0.693+0.223)/3 = 0.842;遮掉第一个 → (0.693+0.223)/2 = 0.458。问题位置的梯度 = 0,不会被往上推。
- 你的输出:34 个 token,9 个问题 token label = −100,loss 只在 25 个回答 token 上平均。
- 目的:只教模型「怎么回答」,不教它「怎么写用户的问题」(练习 2 MASK_USER=False 就是不遮)。
- dpo.py 里没用 −100,而是乘一个 0/1 的 is_ans 再加起来,效果一样。

### Q(2026-11-15 19:36 PT):为啥算完 loss 还要求平均?
- 方向不变,只改大小:求和与求平均的梯度方向一样,平均只是除以 token 数。
- 不平均的问题:loss 和梯度大小会跟着「这批碰巧有多少 token」变。例:每个 token −ln p 都是 0.5,一批 25 个 token → 和 12.5,一批 100 个 → 和 50,模型水平一样,却说后者差 4 倍、梯度大 4 倍 → 同一个 lr 一会儿太大一会儿太小。平均后都是 0.5。
- 好读:平均 loss 能换回「平均每个 token 的概率」:e^(−loss)。测试 loss 4.57 → e^−4.57 ≈ 0.010(正确 token 平均约 1%);0.54 → e^−0.54 ≈ 0.58(约 58%)。不同长度、不同 epoch 之间能直接比。
- 对照 DPO:dpo.py 先把一条回答里的 token **加起来**(因为要整句话的概率 = 每个 token 概率相乘,取 log 就是相加),再在一批里的几对之间**求平均**(理由同上)。

### Q(2026-11-15 21:49 PT):差距是 0 时,loss 和推力具体怎么算?
- σ(x) = 1/(1+e^(−x))。差距 0:e^0 = **1**(不是 0)→ σ(0) = 1/(1+1) = 0.5 → loss = −ln 0.5 = 0.693;推力 = σ(−0) = 0.5。
- 推力的来历:loss 对差距求导 d/dg[−ln σ(g)] = −(1 − σ(g)) = −σ(−g),大小就是 σ(−g)。(1 − 1/(1+e^−g) = e^−g/(1+e^−g) = 1/(1+e^g) = σ(−g))
- 差距从哪来(法国首都):训练前 π=π_ref → r_c = 0.1×(−95.15+95.15) = 0,r_r = 0 → 差距 0。第一轮后 r_c = 0.1×(−44.29+95.15) = 5.09,r_r = 0.1×(−17.34+5.02) = −1.23 → 差距 6.32。
- 差距 6.32:e^−6.32 = 0.0018 → σ = 1/1.0018 = 0.9982 → loss = −ln 0.9982 = 0.0018;推力 = 1/(1+e^6.32) = 1/(1+555.6) = 0.0018。
- 推力怎么用:每个参数的梯度 = β × 推力 × [∇logπ(chosen) − ∇logπ(rejected)]。

### Q(2026-11-15 21:51 PT):解释「推力 = σ(−差距),梯度 = β × 推力 × [推高 chosen − 压低 rejected]」
- 链式法则:loss 只通过「差距」依赖权重 θ;差距 = β[logπ(c) − logπ_ref(c)] − β[logπ(r) − logπ_ref(r)],π_ref 冻结是常数。
  ∂loss/∂θ = ∂loss/∂差距 × ∂差距/∂θ = (−σ(−差距)) × β[∇logπ(c) − ∇logπ(r)]。梯度下降减去它 → 权重往 +β·推力·[∇logπ(c) − ∇logπ(r)] 走。(我之前写的「梯度 =」其实是更新方向,少了负号。)
- ∇logπ(c):每个权重动一点,chosen 整句 log 概率涨多少 —— 和 SFT 在这句话上的梯度一样。所以 DPO 一步 = 对 chosen 做一点 SFT + 对 rejected 做一点「反 SFT」,力度 β × 推力。
- 三个因子:β 固定旋钮(0.1);推力每对不同(已拉开的对几乎不推,还反着的对推力接近 1);方括号 = 方向。
- 例:权重 A:∂logπ(c)/∂A = +2,∂logπ(r)/∂A = −1 → 方向 3。差距 0:0.1×0.5×3 = 0.15;差距 6.32:0.1×0.0018×3 = 0.00054(小 278 倍)。权重 B:两句都 +1 → 方向 0,DPO 不动它 → chosen 和 rejected 共有的部分(比如都有 "in My Orders")得不到推力,DPO 只推两句「不一样」的地方。

### Q(2026-11-15 21:53 PT):为什么要乘 β = 0.1?
- β 就是 KL 绳子的松紧,和 PPO 里 r_t = −β·ln(p/p_ref) 的 β、L2 闭式解 p ∝ p_ref·e^(r/β) 的 β 是同一个东西;DPO 的隐含奖励 r = β·ln(π/π_ref) 就是从那个闭式解倒过来的。
- 作用:决定模型离开 SFT 多远时 DPO 就「满意停手」。要 loss 降到 0.01 需要差距 4.6 → log 概率比的差要到:β=1 → 4.6;β=0.1 → 46;β=0.01 → 460。
- 法国首都那对第一轮的 log 比差 = (−44.29+95.15) − (−17.34+5.02) = 63.18:β=1 → 差距 63 早就停了;β=0.1 → 6.32,推力 0.0018;β=0.01 → 0.63,loss 0.43、推力 0.35,还会接着推很远。
- 公式里 β 出现两次:差距里(决定推力何时变 0,主要作用)和链式法则带出来的那个 β(步子大小,AdamW 会再缩放)。
- 0.1 是 DPO 论文和常用库的默认值,常见范围 0.01~0.5,和学习率一样是调出来的超参数。

### Q(2026-11-15 21:59 PT):DPO 为什么只看整句?所以我的问题在于第一个 token 没被推吗?
- 诊断基本对:第一个 token 没被推够。
- 为什么整句:DPO 从「人比较两个完整回答」+ 闭式解 p(整句) ∝ p_ref(整句)·e^(r/β) 推出来,一对数据只有一个分 = 16 个 token 的 log p 之和,只有一个共同的推力 σ(−差距)。没有 critic、不分功劳(PPO 用 critic + GAE 按 token 分)。好处是简单,代价是不知道哪个 token 是瓶颈。
- 拒答整句 log p 拆开:训练前 −95.15 = Sorry −13.10 + 其余 15 个 −82.05;纯 DPO 后 −44.29 = Sorry −14.99 + 其余 −29.30。总分涨的 51 全来自后面 15 个词,Sorry 反而跌了 1.9。差距(63)够了 → 推力 0.0018 → 所有 token 一起停。Sorry 为什么反而跌:推力很快没了,同时网店数据在同一位置把 Standard/Go 这类开头词往上推(合理推测)。
- 类比:16 门课,DPO 只看总分;生成要每一步都排第一,像每门都得及格,第一门 0 分就整句出不来。
- SFT 项 = 每个 token 的 −log p 取平均,每个 token 的推力 ∝ (1 − 自己的 p),不受「总分够了」影响 → Sorry 一直被推到 0.967(log −0.03)。
- 研究里也有把 DPO 做到 token 级/步骤级的变体(如 TDPO、Step-DPO)。

### Q(2026-11-15 22:14 PT):SFT 项的系数 α(Llama 3 用 0.2)有什么影响?
- α = SFT 项(chosen 每 token −log p 的平均)在总 loss 里的分量:loss = −ln σ(差距) + α × SFT 项。α 越大越像「直接在 chosen 上做 SFT」,越小越像纯 DPO。
- 实测(真 GPT-2):不加「别拒」对:α=0 → 拒答 0/6,网店 4→3;α=0.2 和 1.0 → 都 6/6,但网店 4→3(误拒)。加「别拒」对:α=0.2 → 0/6(推 chosen 的力气比不过「别拒」);α=1.0 → 5/6,网店 4/6。
- 太小:chosen 推不到第一(尤其 chosen 是模型从没说过的话,−95)。太大:SFT 项没有绳子(不跟 π_ref 比),模型会死记 chosen 的说法、离 SFT 越来越远、DPO 从 rejected 学「不该说什么」的作用被冲淡。
- Llama 3 用 0.2:它的 chosen 本来就是自家模型生成、人挑出来的,模型本来就会说;SFT 项只用来稳住训练(防止 chosen 的 log p 跟着一起掉、保持格式)。我们的 chosen 是人写的新句子,所以要 1.0。
- 规律:chosen 离模型现有说法越远,α 要越大(或干脆先 SFT)。

### Q(2026-11-15 22:18 PT):「chosen 的 log p 跟着 rejected 一起往下掉」这个毛病啥意思?
- DPO 只要差距变大:chosen 跌一点、rejected 跌很多,差距照样变大、loss 照样变小,DPO 照样满意。chosen 反而更不可能被说出来,让出的概率流到第三种回答。
- Jet 自己的第一轮(纯 DPO)网店题 12 对:chosen(正确答案)**12/12 全部下降**,平均 −0.76;rejected 平均 −61.72。例 "How do I get a refund?":chosen −3.50 → −4.95(整句概率 3.0% → 0.71%,小了约 4 倍),rejected −14.28 → −76.38;差距 = 0.1×((−4.95+3.50) − (−76.38+14.28)) = 6.07,loss 很小。
- 为什么会跟着掉:chosen 和 rejected 长得像(都是 "Go to My Orders…/You can…"),共享权重;狠压 rejected 时把相似的 chosen 也拖下去一点,DPO 不在乎。
- 后果:第一轮网店测试题答案走样("Standard shipping returns in 3-5 business days"、"Request Request For Money Back"),网店题 4 → 3。
- 加 SFT 项后(第二轮):chosen 12/12 全部上升,平均 +2.39,refund 那句 −3.50 → −1.15(31.7%)。这就是 Llama 3 加 0.2 SFT 项「防止 chosen log p 下降」的意思。

### Q(2026-11-15 22:26 PT):为什么加了 SFT 项又冒出「误拒」?(α=0.2、没有「别拒」对那次:3 道网店题被拒)
- 根因:数据只教了一边 ——「无关问题说 Sorry」,没教「网店问题别说 Sorry」。
- 三股力:① SFT 项把同一句拒答在 12 个问题后面无条件往 100% 推,没有绳子 → 最省事的学法是把 Sorry 当成通用开头;② DPO 项在压网店答案本身:12 个无关问题的 rejected 里 11 个是网店原话(运费 4 次、联系客服 5 次、密码 1、取消 1,另 1 个是乱编);③ 没有任何一对是「网店问题:正确答案 ≻ Sorry」,Sorry 在网店问题上从没被扣过分。
- 被翻的 3 道:parcel(运费答案被当 rejected 压了 4 次)、undo 和 update address(SFT 本来就答错成退款,模型没把握)。不是简单数次数:联系客服答案被压 5 次,那道题却没被拒。
- 修法 2 管用的原因:同一句 Sorry 在无关问题后是 chosen、在网店问题后是 rejected → 不能再靠「Sorry 是好句子」的捷径,只能看问题内容 → 学到边界。偏好数据两边都要有例子。

### Jet 自己复述 DPO 两轮(2026-11-15 22:38 PT,基本正确)
- Jet:DPO 只看差值,chosen 也可能掉,掉的概率流到别的生成;给 loss 加每个 token 的 SFT loss,保证 chosen 的 token 概率提升;但提升后可能误答(误拒),因为 rejected 其实也是正确回答(k+1);所以要加「正确答案 chosen / Sorry rejected」压一下。

- Q:rejected 用「下一个类别的答案(k+1)」是为了简便吗?是。真实做法:同一问题让 SFT 模型采样 2~4 个回答,人或 AI 评委挑好/差(Llama 2/3、UltraFeedback),rejected 通常是模型自己会犯的错,而不是别的问题的正确答案。k+1 的副作用:被压的句子在别的问题里是正确答案,压它会连带伤到它自己的问题(和无关问题 rejected 11/12 是网店原话同理)。

### Q(2026-11-15 22:41 PT):考虑每个 token 的 DPO 变体简单怎么做?
- ① 把隐含奖励按 token 拆开(「From r to Q*」论文):r(整句) = Σ 每个 token 的 β·ln(π(词)/π_ref(词))。法国首都第一轮:整句 +5.09,但 Sorry 这一格 = 0.1×ln(3.1e-7/2.05e-6) = −0.19(负的),一拆就看到瓶颈;修复版 Sorry 这一格 = 0.1×ln(0.967/2.05e-6) = +1.31。可以用来给 token 分功劳。
- ② Step-DPO(数学推理):chosen 和 rejected 共享前面正确的步骤,只在第一个出错的步骤分叉。前缀完全相同 → 两边的 log p 一样,在差距里正好抵消,推力全落在分叉那一步。对应我们:若 rejected 是 "Sorry, please request a refund.",共同前缀 "Sorry," 抵消,只推 " I can only help…" vs " please request a refund."。
- ③ TDPO:差距里再加一项「每个位置整张概率分布和参考模型的 KL」,逐 token 管住漂移,不只看被选中的那个词,防止某些位置跑太远、保持多样性。
- 现状:工业界多用整句 DPO + SFT 项(Llama 3),要逐 token 分功劳就用 PPO/GRPO 这类 RL;token 级 DPO 多在研究里。

### Q(2026-11-15 22:59 PT):「PPO 的 critic 估 V,知道每个回答比预期好多少」—— 不应该是给每个 token 分 V 吗?
- 对,Jet 抓到了我的口误。PPO 的 critic 给**每个 token 位置**一个 V_t → δ_t → GAE → 每个 token 自己的 A_t(您好|亲|点申请|退款 = +1.84/+2.15/+4.15/+1.10,各不相同)。
- GRPO 没有逐 token 的 V,用「同组平均分」当整条回答的基准 → 一条回答只有一个 A,所有 token 共用。例:这条 6 分,组平均 4.5、标准差 1.5 → A = (6−4.5)/1.5 = +1.0,4 个 token 都是 +1.0。
- 代价:功劳分得粗,好回答里的坏 token 也一起被推高,靠大量采样平均掉。DeepSeekMath 论文也给了「过程监督」版 GRPO:按步骤打分,每个 token 的 A = 它后面各步骤(归一化后)分数之和,能逐步分功劳。

### Jet 复述 PPO 的 A(2026-11-15 23:04 PT):「A 取决于 RM 给最后一个 token 打分、倒推,加上 critic 自带的分数算出来,再去训练模型权重」—— 基本对
- 补 3 点:① 每个 token 的奖励还有 KL 扣分 −β·ln(p/p_ref),不只最后一个 token 有分(例 r = [0, −0.092, 0, 6.0]);② 倒推 = GAE:δ_t = r_t + V_{t+1} − V_t,A_t = δ_t + 0.95·A_{t+1},从最后一个 token 往前;③ A 用来改 actor(带 clip);critic 自己用 G = A + V 当目标另外训练。
- GRPO 对比:A = (r − 组平均)/组标准差,没有 critic、不用倒推,整句一个 A。

## Q(11-15 23:35 PT):R1-Distill 的 distill 是什么?

## 第 9 周测验(11-15 23:54 PT)约 2.7/5:结论基本都对,理由和"两种修法/代价/一句理由"没写全
1. RM 被钻空子(0.5):诊断对;只给"加大 KL β",漏代价(β 大学得少)和第二种修法(长度均衡数据重训 RM / 长度惩罚 / 人工抽查早停)。
2. PPO 少模型(0.6):(a) 没参考模型 → 漂向钻空子 ✓(β=0 → 99.8% 长废话);(b) 没价值模型:每个 token 同样的推力,分不出哪个 token 好,且没有基线(RM 分都是正的 → 所有回答都被推高,噪声大、学得慢)。GRPO 用组平均当基线,但同一回答的 token 仍共用一个 A(不解决逐 token 功劳)。
3. DPO 验收(0.5):"差距大 ≠ chosen 上升" ✓;上线后果:概率流向胡编、拒答不生效;SFT 项是训练修法不是验收指标;验收看生成:留出集拒答率、网店题正确率、误拒率。
4. GRPO 不动(0.4):全对多 = 太简单 → 换难题/丢组(动态采样),不是往组里塞错误答案;全错多 = 太难或格式对不上 → 冷启动 SFT、简单题、检查奖励函数、加大 G、部分分。
5. 选型(0.7):SFT / DPO / GRPO / 蒸馏 全对,缺理由:a 有示范学话术;b 有偏好对、离线省(126 vs 252 GB);c 结果可自动判对错 → 规则奖励;d 小模型自己 RL 摸不出长推理(32B: 47.0% vs 72.6%)且贵。

## Q(11-15 23:59 PT):RM 分是什么?
- RM = Reward Model = 奖励模型 = 裁判(L1 reward.py);RM 分 = 裁判读完整个回答给的一个分数(长废话 9.1、简洁准确 6.5)。
- 周测第 2 题"RM 分都是正的":裁判只学分差,绝对值没意义,可能全是正分(好 6.5、差 3.7)。直接当推力 → 差回答也被推高。减基线(预期 5):+1.5 推高 / −1.3 压低。PPO 基线 = 价值模型 V,GRPO 基线 = 组平均。

## Q(11-16 00:02 PT):PPO 的基线就是最开始那个分数(V₀)吗?
- 一半对:V₀ 是整个回答的基线;PPO 每个 token 都有基线 V_t,随回答往下写而变。
- 逐 token 表(您好|亲|点申请|退款,RM 6.0):V 3.7/3.5/1.8/4.9,δ −0.2/−1.79/+3.1/+1.1;四个 δ 之和 ≈ +2.2 = 6.0 − V₀(再扣一点 KL)。V₀ 定整句好了多少,中间 V 把这 +2.2 分给每个 token。
- GRPO 只有相当于 V₀ 的一个基线(组平均),没有中间 V → 同一回答每个 token 同一个 A。

## Q(11-16 00:03 PT):预期 V 是怎么得来的?
- 价值模型(critic)算的:语言模型 + Linear(→1),每个位置出一个数 = "读到这里,预计最后拿几分";一次前向算出全部位置。奖励模型只在最后一个 token 出分。
- 直观:写完"您好"后的多次回答最后拿 6/2/4/3 → V(您好) ≈ 3.75 = 从这一步往后平均能拿多少分。
- 训练:目标 G_t = A_t + V_t,loss = (V_t − G_t)²;第 1 轮随机或从 RM 复制 → 功劳乱;策略在变,"平均"也在变 → 边用边练。

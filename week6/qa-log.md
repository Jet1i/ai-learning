# 第 6 周 提问记录

## L1 Scaling Laws

**Q：这里的 D 是什么？为什么要算一个 D/N？**（2026-11-10）
- D = 训练数据量，训练时模型一共读了多少个 token。别和小写 d（向量维度）搞混。
- D/N = 平均每个参数分到多少个 token 的训练数据。锚定 wx+b：每读一个 token，反向传播把所有 w 各拧一下；D/N 就是每个旋钮被多少数据“教过”。
- 太小（GPT-3 ≈ 2）：模型大但没喂饱，浪费；太大（LLaMA-3 8B ≈ 1875）：故意喂撑，训练不划算但推理便宜；Chinchilla 最优 ≈ 20，且基本不随预算变 → 钱多了，N 和 D 要一起加。

**Q：Scaling Law 就是发现了这个制约关系吗？**
- 对一半。两个发现：① Kaplan 2020：loss 随 N、D、C 按幂律平滑下降，可预测 → 先训小模型拟合曲线，就能预测大模型 loss（各家敢砸钱的底气）。② Chinchilla 2022：预算固定时 N、D 应一起涨，D/N ≈ 20；Kaplan 偏向做大模型，所以 GPT-3 D/N≈2 没喂饱；Chinchilla 70B + 4 倍数据赢了 280B 的 Gopher。
- E=1.69 是地板 → 边际收益递减。

**Q：GPT-3 175B 只配 300B token，是数据不够还是算力不够？**
- 都不是，是故意的：数据集约 500B token 没读完；算力预算 3.14e23 FLOPs 是固定的，问题是怎么分。
- 当时信 Kaplan 2020：算力 ×10 → 模型 ×5、数据 ×2，钱压在参数上。Kaplan 偏差主因：学习率衰减计划没按训练长度调，低估了加数据的好处。
- 按 Chinchilla 重分：约 50B 参数 + 1T token，loss 更低、推理便宜 3 倍多。启示：比模型看“参数 × 训练数据”，不是只看参数。

**Q：所以现在要求高质量数据集，对吗？因为训练取决于参数 × 数据？**
- 对（用词：参数量 × 训练数据量 token，不是“训练参数”）。
- ① 数量：高质量公开文本只有几十 T token，LLaMA-3 8B 已用 15T → “数据墙”。② 质量：A、B 常数依赖数据，干净数据让整条曲线下移（Phi 系列：教科书级数据，小模型赢大模型）。
- 做法：去重、过滤（小模型打分）、合成数据、好数据多读几遍。算力决定能训多大，数据决定训得多好。

**Q：为什么参数越大，token 也要越多？**
- 直觉：y=wx+b 两个参数，2 个点就定了；1000 个参数只给 10 个点，大部分参数没被约束住（停在随机值或死记）。参数是容量，容量大需要更多数据填满。
- 公式：短板效应。只加 N，A/N^α 变小但 B/D^β 不动，成为最大块；钱花在最长的那块上 → N、D 轮流涨。预算 ×10 → N、D 各 ×√10≈3，D/N 基本不变。

**Q：所以决定的还是算力卡吧？卡多 → 预算多 → N、D 都能加 → 模型越强？**
- 同一套配方下对，但漏三件事：① 幂律递减 + E 地板；② 数据墙；③ 效率：同样算力能做多强（DeepSeek-V3 约 280 万 H800 GPU 小时 ≈ 560 万美元，靠 MoE、MLA、FP8），推理时多想（R1）也能换效果。
- 模型能力 ≈ 算力 × 数据质量 × 算法效率。L2 的每处架构改动都是“同算力榨更多效果”。

## L2 LLaMA 块

**Q：GPT-2 的位置向量表 1024 行是啥意思？**
- 注意力本身不知道顺序（狗咬人 = 人咬狗），要额外告诉位置。GPT-2 学一张 1024×768 的表：第 i 行给第 i 个位置，`x = 词向量 + 位置表[i]`。week3/block.py 的 `P = r(10, d)` 是 10 行迷你版。
- 是训练出来的参数（≈79 万）；1024 行 = 上下文上限，第 1025 个词没有行可查。
- 纠正第 3 周误区：上下文长度只影响这张表，其他矩阵与长度无关；LLaMA 用 RoPE 连表都没有。

**Q：1024 决定了单次上下文能输入的 token 数吗？**
- 对。且输入 + 输出共用（生成的 token 也占位置），API 的“上下文窗口 128K”同理。超出只能丢最前面的（第 1 周 chat2.py 只留最近 5 轮）。
- 另一限制：注意力 T×T，长度 ×2 → 计算/显存 ×4。长上下文要解决位置表示（RoPE）和显存（GQA、FlashAttention）。

## L3 RoPE

**Q：q、k 旋转角度怎么能表示位置关系？要存 1024 个角度吗？**
- 不存，公式现算：位置 m 转 m·θ，任意长度都能算。
- q·k = |q||k|cos(夹角)。q 转 mθ、k 转 nθ，夹角只变 (n−m)θ → 分数只看距离。实测 (2,5)(10,13)(100,103) 都是 0.9524；GPT-2 加表三个分数各不同。
- 一个角度转一圈会撞车 → 每两维一组、不同速度（秒针/分针/时针），快的管近距离、慢的管远距离。

**Q：那我把 cos 的“周期”拉高，上下文就能无限长吗？**
- 调大 base（10000 → LLaMA-3 500000）让慢指针更慢，长距离不撞车；数学上任何位置都能算角度。
- 三道坎：① 没见过的角度模型不会用 → 位置插值 / YaRN 压缩回训练范围 + 长文本继续训练；② T² 计算 + KV Cache 显存；③ 装下 ≠ 用好（lost in the middle）。
- 售前：128K ≠ 128K 都能用好，文档多时先 RAG 再给模型。

**Q：忘了 LayerNorm 怎么算**（demo 里加了一步步计算区）
- 作用在每个 token 自己的向量上。例 x=[2,4,6,8]：LayerNorm：μ=5 → 减均值 [-3,-1,1,3] → 方差 5、σ=2.24 → [-1.34,-0.45,0.45,1.34] → ×g+b。
- RMSNorm：平方平均 30 → RMS=5.48 → [0.37,0.73,1.10,1.46] → ×g。不挪中心，只缩大小。

## L2 练习讲评（约 1.3/3）
- 练习 2：12·L·d² + V·d = 6.57B，代码 6.74B，差 0.17B ≠ 偏置 b。主因：LLaMA 输出头不共享词表（GPT-2 输入/输出共用一张 E），多一个 V·d = 0.13B；其余 0.03B 是 FFN 11008 > 10923（凑 256 倍数）。
- 不归一化 → 数值逐层放大/缩小 → 梯度爆炸/消失（Jet 说对了）。
- 练习 3：d=4096，GPT-2 FFN 每层 1.34 亿；SwiGLU 若中间仍 4d → 2.01 亿（1.5 倍）。缩到 8/3 d 是为了参数量相同下公平对比（参数多 loss 本来就降）。

**Q：FFN 的矩阵参数怎么计算？**
- a×b 矩阵 = a·b 个参数。y = x@W，x 有 d 个数 → h 个输出，每个输出要 d 个 w → d×h。例：2→3 是 6 个 w。
- GPT-2 FFN：W1 d×4d + W2 4d×d = 8d²（d=4096 → 1.34 亿）。SwiGLU：3·d·h；h=4d → 12d²（多 50%），h=8/3 d → 8d²。
- 每层 12d² = 注意力 4d²（Wq Wk Wv Wo）+ FFN 8d²；总 12·L·d² + V·d。

**Q：d 就是一个 token 用多少维向量表示吗？**
- 对，隐藏维度/模型宽度（GPT-2 small 768，LLaMA-2 7B 4096）。贯穿全模型：每层进出都是 d 维（残差能相加），FFN 临时放大 4d，最后输出变 V 维。
- 参数量 ∝ d²；变大靠加宽 d + 加深 L（7B→70B：d 4096→8192，L 32→80）。
- 区分：d 向量长度、T 上下文长度、D 训练数据量、V 词表大小。参数量只和 d、L、V 有关。

**Q：维度放大的含义？能表达更复杂的信息？**
- 对。① 模型 d 变大：每个 token 能带更多特征（动物与否、褒贬、时态、领域…），代价 ∝ d²。② FFN 临时放大到 4d：4d 个“检测器”（每个都是 wx+b + 激活，匹配模式就亮），压回 d 时把对应信息写回 → FFN 是存知识的地方（占每层 2/3 参数）。
- d = 每个 token 能带多少信息；FFN 的 4d = 每层能查多少条规律。收益递减（Scaling Law）。

**Q：GPT-2 和 LLaMA 的 QKV 那里都是 4d² 吗？**
- GPT-2、LLaMA-1、LLaMA-2 7B/13B：4d²。LLaMA-2 70B、LLaMA-3 用 GQA：LLaMA-3 8B 中 Wq d²、Wk/Wv 各 4096×1024 = d²/4、Wo d² → 2.5d²。
- GQA 重点是省推理 KV Cache 显存（1/4），不是省参数（L4）。

**Q：LLaMA 输出另用 V×d 矩阵？不是说 LLaMA 不用词表、用角度表示吗？**
- 混了两张表：词表 E（V×d，每个词一行）和位置表 P（1024×d，每个位置一行）。LLaMA 去掉的是位置表（换 RoPE），词表还在。上下文长度只和位置表有关。
- 输出头 W_out（d×V）把最后的 d 维向量变成 V 个词的分数（logits）。GPT-2 复用词表 E（共享）；LLaMA 单独学一个，多一份 V×d。
- LLaMA：词表 ✓ 输出头 ✓ 位置表 ✗；GPT-2：词表 ✓ 位置表 ✓ 输出头借词表。

**Q：也就是能表示 32000 个 token？**
- 对：V=32000 是词表里有多少种 token（积木种类），不是上下文长度 T（一次放多少块）。
- LLaMA-3 词表扩到 128256：中文/代码切得更省 → 更便宜、同上下文装更多；代价 V×d 两份 ≈ 10 亿参数。售前：比价要看同一段中文切出多少 token。

**Q：q、k 和 Wq、Wk 有什么区别？**
- Wq 是 w（参数，d×d，训练学出、固定、所有 token 共用）；q 是 y（q = x@Wq，每个 token 一个，每次现算）。机器 vs 产品。“狗咬人”：一个 Wq → 三个 q。
- 用处：参数量数 Wq；RoPE 转 q、k（位置属于每个 token）；KV Cache 存 k、v（结果），对话越长越大。

## L3 练习讲评（约 2.2/3）
- 练习 2：base 不是上下文长度。d=64 时最慢指针一圈：base 10000 → 约 4.7 万位置；500000 → 约 208 万位置。长距离不撞车，128K 内角度落在易学范围。
- 练习 3 缺数据：300 页 ≈ 15~20 万中文 token，可能超 128K；每次问都付 15 万 token，RAG 约 2000 token，便宜几十倍。替代：RAG / 长上下文 + 提示缓存。取舍：一次性通读用长上下文，高频问答用 RAG。

**Q：长文本“中间会遗忘”和“模型没训练过”是什么意思？**
- 没训练过：训练最长 8K，慢指针只转到某角度（如 1/4 圈），Wq/Wk 只在这些角度下学过；100K 时角度组合没见过 → 分数乱 → 输出崩。比喻：只练过 0~3 点的钟。解法：位置插值（位置号 ÷12 压回 0~8K 角度）+ 长文本继续训练。
- Lost in the middle（训练长度内也会）：答案在开头/结尾准、在中间差，U 形。原因：训练数据习惯、RoPE 偏近、长序列注意力被稀释。实战：关键信息放开头/结尾、长文档用 RAG、用“大海捞针”测试评估。

**Q：把 cos 所有角度都训练完，不就没有“没训练过”的情况了？**
- 快指针短文本里早就转遍了；卡在慢指针（base 10000 一圈 4.7 万位置），要几万 token 长文本才能覆盖。
- 慢指针调快 → 转完一圈会撞车（隔 0 和隔一圈分不清）。慢了覆盖不到、快了撞车，两难。
- 位置 = 所有指针角度的组合，长距离组合只在长文本出现；模型还得学会长距离怎么用信息。
- 实际：主体用 4K~8K 训练，最后加长上下文阶段（插值/调大 base + 长文本训练到 128K）。标称长度内基本训练过，超过才会崩；训练过 ≠ 用得好。

**Q：注意力是 T×T 什么意思？T 是什么？和 12d² 的关系？**
- T = 本次输入的 token 数。T×T = 每个 q 和每个 k 打分的注意力分数表（狗咬人 3×3=9）；长度 ×2 → ×4。
- 12d² 是参数（固定、与 T 无关）；T×T 是现算的结果（不占参数，占计算和显存）。
- 每层计算：参数矩阵约 24·T·d²（∝T），注意力约 4·T²·d（∝T²），比值 T/6d；d=4096 时分界约 2.4 万 token。长上下文贵在 T²（FlashAttention 第 7 周）。

**Q：那 q、k、v 就是 embedding 吧？**
- 不完全是。embedding = 词表 E 查出的一行，只在最开始用；x = 每层输入（第 1 层是 embedding，之后是上层输出）；q、k、v = 每层从 x 现算（x@Wq 等），三个角色：找什么 / 怎么被找 / 交出什么。
- q·k 是一个数（T×T 表的一格）；没有 “qv”：softmax(q·k/√d) 给 v 加权求和。KV Cache 存的就是每层每个 token 的 k、v。

**Q：注意力是 q、k 构成 T²？q、k、v 是从 Wq、Wk、Wv 得来的？**
- 对：T 个 q × T 个 k = T² 个分数，每个是 d 维点积（约 T²·d 次乘法）；每层每头一张（7B：32×32 = 1024 张）。
- q = x@Wq：x 和 W 两样相乘（例 x=[1,2]，Wq=[[1,0],[1,3]] → q=[3,6]）。
- 完整链：token → embedding x → x@Wq/Wk/Wv → q·k 得 T×T 分数 → softmax 给 v 加权 → 输出。

**Q：Wq Wk Wv 一共多少参数？为什么是 4d²？**
- Wq、Wk、Wv 各 d×d → 3d²；第 4 个是 Wo：多头结果拼起来后乘 d×d 的 Wo，把各头的发现混合。
- GPT-2 small：768² = 589,824，×4 ≈ 236 万/层。
- 多头不加参数：768 切成 12 头 × 64 维，Wq 仍是一个 768×768。每层 4d² + 8d² = 12d²。

**Q：那不分头就是 3d² 了？**
- 理论上对：单头时 Wv@Wo 是两个 d×d 相乘，可合并成一个，Wo 多余。多头时 Wo 负责混合各头结果。实际实现统一保留 Wo，按 4d² 记。

**Jet 的总结（07:21）：T 是 token 数，算注意力是 T×T，遮罩只算一半，每格是 q·k。**
- 修正：一个 token 算一行（T 个分数）；整句一起算（训练/读入 prompt）才是 T×T。生成时每次只算新 token 那一行，前面 k、v 从 KV Cache 拿（L4）。

**Q：q、k、v 是一个值吗？怎么算？x 是什么？**
- x = 每个 token 的向量（第 1 层查词表，之后是上层输出）。例 d=2：x狗=[1,0] x咬=[0,1] x人=[1,1]；Wq=[[1,0],[0,2]]，Wk=[[0,1],[1,0]] → q人=[1,2]，k狗=[0,1] k咬=[1,0] k人=[1,1]。
- q、k、v 是向量（d 个数）；q·k 是一个数：q人 那一行 = [2,1,3] → softmax → 给 v 加权求和。
- x（向量）× W（矩阵）= q/k/v（向量）；q·k = 分数（一个数）。

**Q：算完 q·k 下一步 softmax，然后 v 算权重，v 加起来是 1？temperature 就是这里不除以 √d？**
- 顺序：q·k → ÷√d → softmax 得权重（加起来 = 1）→ 权重给 v 加权求和。例：[2,1,3] → [1.41,0.71,2.12] → [0.28,0.14,0.58] → 0.28v狗 + 0.14v咬 + 0.58v人。v 是内容，不用和为 1。
- temperature ≠ √d：√d 在每层注意力内部、固定、防分数过大；temperature 在最后输出层、除 V 个词的 logits、API 里自己设、控制随机性。共同点：softmax 前除一个数，越大越平。

**Q：LayerNorm 是干啥的？**
- 每个子层干活前把输入向量的“音量”调回标准大小。残差一路往上加，32 层后数值可能过大/忽大忽小 → q·k 过大 softmax 太尖、梯度爆炸/消失、loss 变 NaN。
- 只作用于每个 token 自己的向量；g（b）可学，允许再缩放；Pre-Norm 只归一化子层输入，残差主干不动；输出前还有一个 norm。

## L4 练习讲评
- 练习 1 ✅：LLaMA-3 8B 128K 一条对话 KV Cache ≈ 17 GB（16 GiB），比模型权重还大。
- 练习 2 🟡：GQA vs MQA 权衡的是显存 vs 效果（MQA 质量降、训练不稳）；速度是附加好处。
- 练习 3（需要带着算）：权重 16 GB + 4 GB → 剩约 60 GB；每人 8K 缓存 ≈ 1 GB → 约 60 路 < 200。三段式：数据（约需 4 张卡）；替代（平均长度更短、vLLM 按需分配、KV Cache 8 位量化、限上下文）；取舍（在线人数 ≠ 同时生成数，先压测再买卡）。

**Q：80 亿参数 × 2 字节 = 16 GB 啥意思？**
- 每个参数是一个数，fp16/bf16 每个占 2 字节（fp32 4、int8 1、int4 0.5）。8B × 2 = 16 GB，必须全放进显存。
- 速算：fp16 显存 GB ≈ 参数(B) × 2。8B → 16 GB（24GB 消费卡可放）；70B → 140 GB（≥2 张 A100 80G）；int4 量化 70B ≈ 35 GB（第 7 周）。KV Cache 公式里的 ×2 同理。

**Q：每人 8K 的 KV Cache 怎么算的？**
- 一个 token 一层的 k：8 组 × 128 = 1024 个数；×2（k 和 v）；×32 层 = 65536 个数；×2 字节 = 128 KB/token；×8192 token = 1 GB。
- 公式：2(K,V) × 层数 × K/V 组数 × 每组维度 × token 数 × 字节数。用组数 8 而不是 Q 头数 32。
- 记住：LLaMA-3 8B 每 token 128 KB（8K → 1 GB，128K → 16 GB）；MHA 是 512 KB/token。

**Q：MQA “质量下降、训练不稳”啥意思？KV 不是省推理预算的吗，为啥和质量有关？**
- GQA/MQA 是结构改动，训练时就是这样：Wk、Wv 本身变小，省缓存是结果。
- 多头的意义：不同头找不同关系；MHA 每头一份 k/v（专属简历），MQA 32 头共用一份 → 表达不足、质量降、训练易不稳；GQA 8 份够用，效果接近 MHA、缓存 1/4。
- 训练前的设计选择：不能对训好的 MHA 推理时直接砍 K/V（需再训练转换）。同思路：量化（第 7 周）、MLA（第 8 周）。

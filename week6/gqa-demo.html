KV Cache 与 GQA:推理时显存都去哪了?

生成每个新 token 时,它的 q 要和前面所有 token的 k、v 做注意力。这些 k、v 不会变,所以存起来复用,叫 KV Cache。代价:对话越长,存得越多。

① 生成过程:每多一个 token,每个 K/V 组就多存一格
K/V 分组:

左边 8 个 Q 头(每个头还是独立地"看"),连线表示它用哪一组 K/V。右边每一格 = 一个 token 的一份 k+v。格子总数 = 缓存大小。

② 一张 80GB 显卡部署 8B 模型(fp16):能同时服务多少对话?

参数按 LLaMA-3 8B:32 层、32 个 Q 头、每头 128 维。灰 = 模型权重约 15GB + 4GB 计算空间;彩色 = 被 KV Cache 占满的显存,每一小条 = 一条对话。拖到 32K、128K 看 MHA 还剩几条。
